# S9 小程序端页面交接

## 1. 阶段结论

| 项目 | 结论 |
|---|---|
| 阶段 | S9「小程序端页面」 |
| 范围 | 仅处理 `frontend/miniprogram` 学员端页面，并补充 `frontend/shared` 端侧清单；未读取、参考或复用 `D:\java-code\wecom-BFT-system-old-failed` |
| 前端入口 | `frontend/miniprogram`，微信小程序原生目录 + TypeScript |
| Workspace | 已新增 `@wecom-bft/miniprogram` 包并加入 `pnpm-workspace.yaml`，根 `pnpm build` 会覆盖小程序 TypeScript 构建并生成微信开发者工具可导入的 `frontend/miniprogram/dist/` |
| 完成结论 | 小程序从 S1 占位页升级为可导入微信开发者工具的学员端页面集，覆盖登录授权、课程、下单支付、订单、学习、退款、发票、物流摘要、通知/地址缺口页 |
| 接入原则 | 以当前 Controller/DTO 为准；支付成功必须调用后端 `/pay` 和 `/mock-pay` 后重新查询订单；写操作统一通过请求层生成 `Idempotency-Key` |

## 4. 06 文档与当前 Controller/DTO 差异

| 差异 | 当前代码事实 | S9 处理 |
|---|---|---|
| 微信登录请求字段 | 当前 `AppWechatLoginRequest` 只有 `wxCode`、`sourceChannel`，后端只接受 `mock:` 登录码 | 按当前 DTO 发送 `wx_code=mock:*`，不发送 `encrypted_data`、`iv` |
| 手机号授权请求字段 | 当前 `PhoneAuthorizeRequest` 只有 `phoneCode`，不接 `wx_openid`、`student_id` | 按当前 DTO 发送 `phone_code=mock:*` |
| 交易前置接口 | 当前存在 `POST /api/app/trade/precheck`，06 未列为主接口 | 服务层保留；页面仍以写接口服务端校验为最终裁决 |
| 课程规格接口 | 当前存在 `GET /api/app/courses/{course_id}/specs`，06 未单列 | 课程详情已直接返回 `specs[]`，页面未额外调用 |
| Mock 支付接口 | 当前存在 `POST /api/app/orders/{order_id}/mock-pay`，06 主要描述统一回调 | 页面调用该后端 Mock 入口，该入口内部走回调处理链路；页面随后重查订单 |
| 退款申请路径 | 当前同时支持 `POST /api/app/refunds` 与 `POST /api/app/orders/{order_id}/refunds` | 页面接资源路径 `/api/app/orders/{order_id}/refunds` |
| 开票申请路径 | 当前同时支持 `POST /api/app/invoices` 与 `POST /api/app/orders/{order_id}/invoices` | 页面接资源路径 `/api/app/orders/{order_id}/invoices` |
| App 发票详情 | 06 有 `GET /api/app/invoices/{invoice_id}`，当前 Controller 只有 `GET /api/app/invoices` | 页面从列表按 `invoice_id` 定位，并记录缺口 |
| 地址接口 | 06 有 `/api/app/addresses`，当前无 Controller | 页面展示接口缺口，不本地伪造地址 |
| 物流详情 | 06 有 `/api/app/orders/{order_id}/logistics`，当前无 App Controller | 页面使用订单详情 `shipments[]` 摘要，并记录缺口 |
| 通知列表/已读 | 06 有 `/api/app/notifications` 和已读接口，当前无 App Controller | 页面展示接口缺口 |
| `allowed_actions[]` | 当前小程序订单、退款、发票 DTO 未返回 `allowed_actions[]` | 页面按后端状态字段做体验层按钮判断，最终仍由后端接口裁决 |
| 学习权益 `course_snapshot` | 06 描述为对象，当前 `EntitlementItem.courseSnapshot` 是字符串 | 页面解析 JSON 字符串，解析失败时只展示原文摘要 |
| 发货信息字段 | 06 期望物流公司、运单号、轨迹；当前订单详情 `ShipmentResponse` 不含运单号和轨迹 | 物流页只展示发货单状态、收货快照和异常信息 |

## 5. 联调记录

| 链路 | 当前处理 | 结果 |
|---|---|---|
| 登录态持久化 | `session.ts` 存储 `accessToken/studentId/studentNo/mobileBound/mobile` | 刷新或重新进入可恢复关键登录态 |
| 未授权手机号拦截 | `canCreateOrder()` 在订单确认/提交前拦截；后端写接口继续兜底 | 页面不允许未授权手机号提交订单 |
| 订单创建幂等 | `http.ts` 在 `idempotent=true` 写接口统一追加 `Idempotency-Key` | 创建订单、退款申请、开票申请、发票抬头保存已接入 |
| Mock 支付 | `payWithBackendMock()` 依次调用 `/pay`、`/mock-pay`、`GET /orders/{id}` | 不直接改前端状态，最终显示以后端订单状态为准 |
| 写后重查 | 支付、取消订单走写后重查；退款/开票写后跳详情或列表定位 | 避免前端硬编码业务状态流转 |
| 金额展示 | `formatCent()` 只做整数分转元展示 | 不用浮点参与业务计算 |
| 敏感字段 | 手机号只按后端返回内容展示，并在本地档案处做基础脱敏 | 不伪造后端未返回字段 |

## 7. 接口缺口

| 缺口 | 影响 | 建议 |
|---|---|---|
| 缺少 `/api/app/addresses` 地址列表、保存、删除、设默认 | 含实物订单无法从页面新增/选择地址，只能在有既有 `address_id` 的情况下确认 | S10/S11 前补 App 地址 Controller/DTO；确认接口继续以后端地址归属校验为准 |
| 缺少 `/api/app/orders/{order_id}/logistics` | 小程序物流页无法展示物流公司、运单号和轨迹时间线 | 复用发货单与 `logistics_trace`，补 App 只读物流详情接口 |
| 缺少 `/api/app/notifications`、`/api/app/notifications/{id}/read` | 学员无法独立查看全部通知和标记已读 | 补 App 通知列表、详情/已读接口；站内通知仍应为必达 |
| 缺少 `/api/app/invoices/{invoice_id}` | 发票详情只能从列表中过滤定位 | 补 App 发票详情接口，并校验发票归属 |
| 业务详情缺 `allowed_actions[]` | 小程序按钮只能按状态字段做体验层判断，不能完全表达权限与状态裁剪 | 建议订单、退款、发票、物流详情补 `allowed_actions[]` |
| 发货摘要缺运单字段 | 订单详情中 `shipments[]` 不含物流公司和运单号 | `ShipmentResponse` 或物流详情接口补 `logistics_company_name`、`tracking_no` |

## 9. S10 注意事项

| 事项 | 说明 |
|---|---|
| 不扩散 PC 缺口 | S8 已知 `/api/admin/students`、`/api/admin/suppliers` 不属于 S9 主目标，本阶段未处理 |
| 外部协同端不要复用小程序 Token | 小程序使用学员 Token；企微侧边栏/供货商 H5 必须按各自鉴权边界接入 |
| Mock 仍需走正式链路 | 支付、退款、物流、开票等 Mock 不应在前端直接改状态；继续依赖后端 Mock/回调链路 |
| 补 App 缺口时先补 DTO | 地址、通知、物流、发票详情建议先补 Controller/DTO 与测试，再让小程序页面从缺口态切换为真实数据 |
| `allowed_actions[]` 优先级 | 后续若后端补动作字段，小程序按钮应改为优先使用 `allowed_actions[]`，状态字段仅作兜底展示 |
