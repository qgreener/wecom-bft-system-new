## 2. 部署目标与环境假设

### 2.1 部署目标

| 部署目标 | 说明 | 验收关注点 |
|---|---|---|
| 服务器可访问 | 通过公网或演示内网访问统一入口，Nginx 代理后端 API 并托管前端静态资源。 | PC、H5、API、回调路径均能访问；Nginx 访问日志可追踪。 |
| PC 管理端 | 支持内部角色登录、菜单权限、订单、退款、发货、开票、对账、代账、配置、审计和异常补偿演示。 | `/admin/` 可打开并调用 `/api/admin/**`。 |
| 小程序接口 | 支持微信小程序端课程、下单、支付、学习、退款、发票、地址、物流和通知接口。 | 小程序请求合法 HTTPS 域名下的 `/api/app/**`。 |
| 企微侧边栏 | 支持企业微信侧边栏 H5 和接口联调，识别外部联系人并展示线索、学员和订单摘要。 | `/h5/wecom-sidebar/` 和 `/api/wecom/sidebar/**` 可用。 |
| 供货商 H5 | 支持供货商确认采购、拒绝接单、填写物流、回填进项发票。 | `/h5/supplier/` 和 `/api/supplier-h5/**` 可用。 |
| 公开留资 H5 | 支持匿名留资并形成线索。 | `/h5/lead/` 可访问并提交到后端。 |
| 外部回调入口 | 支持支付、退款、物流、开票、红冲、企微审批和企微卡片回执回调。 | `/api/callbacks/**` 走 HTTPS、公网可达、后端验签和幂等落库。 |
| Mock 演示 | 在无真实平台凭证时，用 Mock 替代外部系统，演示成功、失败、重复回调、乱序回调、异常待处理和人工补偿。 | Mock 不绕过业务状态机，不新增演示专用状态。 |

### 2.2 推荐服务器环境

| 组件 | 建议方案 | 用途 | 确认状态 |
|---|---|---|---|
| 操作系统 | Linux x86_64，建议 Ubuntu Server 22.04 LTS / Debian 12 / Rocky Linux 9 | 承载 Nginx、后端服务、数据库、Redis、对象存储或本地文件目录 | 建议方案，待项目实现后确认 |
| JDK | Java LTS，建议 JDK 17 或 JDK 21 | 运行 Spring Boot 3.x 后端服务 | 建议方案，最终以 `backend/pom.xml` 或构建配置确认 |
| 后端框架 | Java + Spring Boot 3.x + MyBatis / MyBatis-Plus | 模块化单体、REST API、事务、权限、回调、补偿任务 | 建议方案，待实现后确认 |
| Node.js | Node.js LTS | 构建 PC 管理端、H5 和小程序相关前端包 | 建议方案，待实现后确认 |
| 包管理器 | pnpm | 前端多应用依赖和构建 | 建议方案，待实现后确认 |
| 数据库 | MySQL 8.x | 保存订单、支付、退款、发货、发票、对账、代账、回调、审计和配置数据 | 建议方案 |
| 缓存 | Redis 稳定版本 | 登录态辅助、短期幂等、分布式锁、热点配置和轻量任务状态 | 建议方案 |
| 文件存储 | MinIO / S3 兼容对象存储；演示环境可本地挂载目录 | 保存发票、红冲凭证、退款凭证、面单、对账文件、代账材料 | 建议方案 |
| 反向代理 | Nginx 1.22+ 或发行版稳定版本 | 统一 HTTPS、静态资源、API 代理、回调入口、上传大小限制和访问日志 | 建议方案 |
| 进程管理 | Docker Compose 默认；systemd Java 进程备选 | 管理后端、Nginx、MySQL、Redis、MinIO 等服务启动和重启 | 最终服务器部署默认采用 Docker Compose |
| 证书 | 可信 CA 签发的 HTTPS 证书 | 微信小程序、企业微信、微信支付等公网回调和端侧访问要求 | 必须准备，真实域名待部署时配置 |

## 3. 服务器目录规划

> 以下目录为服务器建议规划，不表示当前仓库已经存在部署脚本或构建产物。实际路径可按运维条件调整，但需保持应用、配置、日志、文件和备份分离。

| 目录 | 用途 | 建议内容 | 权限与注意事项 |
|---|---|---|---|
| `/opt/wecom-bft-new-system/backend/` | 后端服务目录 | 后端 JAR、启动脚本、版本标识、健康检查脚本 | 仅部署用户和运维用户可写；不放真实密钥明文。 |
| `/opt/wecom-bft-new-system/web/admin/` | PC 前端静态资源目录 | `frontend/admin` 构建后的 `dist` 文件 | Nginx 只读托管；HTML 建议不强缓存，带 hash 的资源可长缓存。 |
| `/opt/wecom-bft-new-system/web/h5/wecom-sidebar/` | 企微侧边栏 H5 构建产物目录 | 企微侧边栏 H5 静态资源 | 需要和企微 JS-SDK 域名配置一致。 |
| `/opt/wecom-bft-new-system/web/h5/supplier/` | 供货商 H5 构建产物目录 | 供货商 H5 静态资源 | 只能通过供货商令牌访问业务接口，静态页面不代表已授权。 |
| `/opt/wecom-bft-new-system/web/h5/lead/` | 公开留资 H5 构建产物目录 | 公开留资页静态资源 | 匿名访问，后端接口必须做频率限制和表单校验。 |
| `/opt/wecom-bft-new-system/release/miniprogram/` | 小程序构建产物归档目录 | 上传微信公众平台前的构建包或版本记录 | 小程序包不由服务器直接托管；是否保留归档待实现后确认。 |
| `/etc/wecom-bft-new-system/` | 配置文件目录 | `.env`、`application-prod.yml` 模板实例、Nginx 片段、证书引用路径 | 仅服务端读取；真实密钥不提交仓库，不写入文档。 |
| `/var/log/wecom-bft-new-system/backend/` | 后端应用日志目录 | 应用日志、错误日志、回调处理摘要日志、任务日志 | 日志需脱敏，定期轮转，避免磁盘打满。 |
| `/var/log/nginx/wecom-bft-new-system/` | Nginx 日志目录 | 访问日志、错误日志、回调入口访问日志 | 用于排查 404、代理失败、回调不可达。 |
| `/data/wecom-bft-new-system/files/` | 上传文件和业务文件目录 | 发票文件、红字发票、退款凭证、采购进项票、面单、对账导入文件、代账材料、导出文件 | 演示环境可本地挂载；生产建议对象存储；不得把物理路径直接暴露给前端。 |
| `/data/wecom-bft-new-system/minio/` | MinIO 数据目录 | 对象存储桶数据 | 如采用 MinIO 时使用；备份时需和数据库文件引用保持一致。 |
| `/data/wecom-bft-new-system/mysql-backup/` | 数据库备份目录 | `mysqldump`、物理备份、演示前快照 | 限制访问权限，定期清理，备份文件可加密。 |
| `/opt/wecom-bft-new-system/scripts/` | 脚本目录 | 启停、健康检查、数据库备份、恢复、演示数据重置脚本 | 脚本待实现后确认；必须可重复执行，不直接覆盖生产数据。 |
| `/opt/wecom-bft-new-system/deploy/nginx/` | Nginx 配置模板目录 | 站点配置、路径代理、静态资源缓存策略模板 | 模板不包含真实域名和证书私钥。 |

## 5. 部署步骤

> 下列步骤按服务器演示和交付环境编写。最终部署方式为服务器 Docker Compose；涉及构建命令、脚本名称、Flyway 执行方式的细节需在项目实现后确认。

### 5.1 部署步骤总览

| 顺序 | 步骤 | 目标 | 产出或检查点 |
|---|---|---|---|
| 1 | 服务器基础环境准备 | 安装运行依赖、创建部署用户、目录、证书和防火墙规则 | JDK、Node.js、MySQL、Redis、Nginx、文件目录可用 |
| 2 | 数据库初始化 | 创建新系统数据库、账号、表结构和演示种子数据 | Flyway 迁移成功，演示账号和基础数据可用 |
| 3 | 后端构建与启动 | 构建后端服务并以 demo/test/prod 配置启动 | 后端端口监听，健康检查通过 |
| 4 | PC 前端构建与 Nginx 配置 | 构建 PC 管理端并发布到 `/admin/` | 页面可打开，刷新不 404，API 代理正常 |
| 5 | 企微侧边栏/H5/供货商 H5 页面部署 | 构建 H5 静态资源并配置独立访问路径 | `/h5/wecom-sidebar/`、`/h5/supplier/`、`/h5/lead/` 可访问 |
| 6 | 小程序接口域名配置 | 在微信平台配置合法请求域名和业务域名 | 小程序能访问 HTTPS API |
| 7 | 外部回调地址配置 | 在支付、退款、物流、发票、企微平台或 Mock 配置中登记回调地址 | `/api/callbacks/**` 公网可达 |
| 8 | Mock 模式启动 | 配置外部能力为 Mock 并加载 Mock 场景 | 成功、失败、重复、乱序等 Mock 回调可投递 |

### 5.2 详细步骤

| 步骤 | 操作说明 | 注意事项 |
|---|---|---|
| 服务器基础环境准备 | 创建部署用户；安装 JDK、Node.js、pnpm、MySQL、Redis、Nginx；按目录规划创建 `/opt`、`/etc`、`/data`、`/var/log` 目录；配置服务器时区、磁盘空间和防火墙。 | 不开放 MySQL、Redis 公网端口；Nginx 暴露 80/443；后端端口仅允许本机或内网访问。 |
| 证书准备 | 为 PC/H5/API/回调域名配置可信 HTTPS 证书。 | 微信小程序、企业微信和支付回调通常要求可信 HTTPS，演示域名也应准备证书。 |
| 数据库初始化 | 创建新系统数据库和最小权限应用账号；执行 Flyway 迁移；导入演示 seed。 | 迁移目录建议为 `backend/src/main/resources/db/migration/`；种子数据建议放 `database/seed/`，实际脚本待实现后确认。 |
| 后端构建 | 建议使用 Maven 构建后端，如 `mvn clean package -DskipTests`；最终以项目实际构建工具为准。 | 构建命令待实现后确认；发布物建议带版本号和构建时间。 |
| 后端启动 | 默认用 Docker Compose 管理后端和依赖服务；启动时指定 `APP_ENV`、数据库、Redis、文件存储、接入模式等环境变量。 | 启动日志不得输出真实密钥；启动失败先查看 container 日志；非容器化部署才使用 systemd 日志。 |
| PC 前端构建 | 在 `frontend/admin` 安装依赖并构建，构建产物发布到 `/opt/wecom-bft-new-system/web/admin/`。 | 构建命令、环境文件和 API Base URL 待实现后确认；前端只允许使用公开配置。 |
| Nginx 配置 | 配置 `/admin/` 静态资源、`/api/**` 反向代理、`/api/callbacks/**` 回调代理、上传大小限制和访问日志。 | SPA 刷新使用 `try_files` 回退到 `index.html`；回调路径需保留请求体和必要 Header。 |
| H5 构建与发布 | 分别构建企微侧边栏 H5、供货商 H5、公开留资 H5，发布到对应 `/h5/**` 目录。 | 企微侧边栏需和企微 JS-SDK 域名、可信域名配置一致。 |
| 小程序接口域名配置 | 在微信公众平台配置 `https://<api-domain>` 为合法请求域名，并在小程序环境中指向 `/api/app/**`。 | 小程序包不直接部署在服务器；正式上传、体验版、审核发布流程在微信平台完成。 |
| 外部回调地址配置 | 为支付、退款、物流、电子发票、红冲、企微审批、企微卡片配置对应回调路径。 | 不在文档中写真实地址；真实平台配置需和 `APP_CALLBACK_PUBLIC_BASE_URL` 保持一致。 |
| Mock 模式启动 | 将 `INTEGRATION_*_MODE` 设置为 `mock`；加载演示数据和 Mock 场景。 | Mock 只替代外部系统，业务状态仍通过统一回调链路推进。 |
| 沙箱/真实模式切换 | 将对应能力切换为 `sandbox` 或 `real`，配置平台凭证、证书、回调地址和签名校验。 | 切换前备份配置和数据库；敏感凭证变更通常需要重启，后台配置能力待实现后确认。 |
| 健康检查 | 验证后端健康、数据库连接、Redis 连接、文件存储、Nginx 访问、回调入口和核心演示流程。 | 使用 `/api/health` 和 `/api/health/ready`，后者需覆盖数据库、Redis 和文件存储状态。 |

### 5.3 建议启动方式

| 方式 | 适用场景 | 建议口径 | 确认状态 |
|---|---|---|---|
| Docker Compose | 服务器默认部署、测试、毕设演示单机环境 | 统一编排 MySQL、Redis、MinIO、后端和 Nginx；便于重建演示环境 | 最终交付默认采用 `deploy/docker-compose.yml` |

## 6. Nginx 与访问入口规划

### 6.1 访问路径规划

| 访问入口 | 建议路径 | 指向 | 权限与说明 |
|---|---|---|---|
| PC 管理端 | `/admin/` | `/opt/wecom-bft-new-system/web/admin/` | 内部人员登录后访问；刷新需回退到 `index.html`。 |
| PC 管理端 API | `/api/admin/**` | 后端服务 | 企业微信扫码或工作台登录态，后端做角色、按钮、数据范围和脱敏校验。 |
| 小程序 API 前缀 | `/api/app/**` | 后端服务 | 学员微信登录态；交易前必须手机号授权。 |
| 企微侧边栏页面 | `/h5/wecom-sidebar/` | 企微侧边栏 H5 静态资源 | 需企微 JS-SDK 上下文和内部登录态。 |
| 企微侧边栏 API | `/api/wecom/sidebar/**` | 后端服务 | 校验企微上下文签名、内部登录态和运营数据范围。 |
| 供货商 H5 页面 | `/h5/supplier/` | 供货商 H5 静态资源 | 页面可访问不代表有业务权限，接口必须校验供货商令牌。 |
| 供货商 H5 API | `/api/supplier-h5/**` | 后端服务 | 仅允许访问当前 `supplier_id` 采购单。 |
| 公开留资 H5 | `/h5/lead/` | 公开留资 H5 静态资源 | 匿名访问，接口需频率限制、手机号校验和来源记录。 |
| 审批通知与补偿 API | `/api/collab/**` | 后端服务 | 内部登录态或企微回调签名；承接待办、通知、审批和异常补偿。 |
| 外部回调入口 | `/api/callbacks/**` | 后端服务 | 平台签名、时间戳、事件号和幂等处理；公网 HTTPS 可达。 |
| 受控文件下载 | `/api/admin/files/**`、`/api/app/files/**`、`/api/supplier-h5/files/**` | 后端文件下载接口 | 后端鉴权后返回临时 URL 或文件流，不直接暴露存储路径。 |

### 6.2 静态文件访问策略

| 文件类型 | 策略 |
|---|---|
| PC/H5 `index.html` | 建议 `no-cache` 或短缓存，避免版本发布后仍打开旧入口。 |
| 带 hash 的 JS/CSS/图片 | 可配置长缓存，例如 7 到 30 天；发布新版本依赖文件名 hash 更新。 |
| 小程序包 | 不由 Nginx 托管；通过微信公众平台上传体验版、审核版和正式版。 |
| Mock 演示占位文件 | 如面单、发票 PDF 占位文件，也应作为业务文件写入 `sys_file_asset`，通过受控下载访问。 |

### 6.3 上传文件访问策略

| 项目 | 策略 |
|---|---|
| 上传入口 | 统一走后端文件上传接口；如后续启用对象存储直传，也必须由后端签发临时授权。 |
| 下载入口 | 下载必须校验登录态、角色、数据范围、业务对象归属和字段脱敏权限。 |
| 物理路径 | 前端、接口响应和日志不得暴露服务器绝对路径；业务表优先保存 `file_no` 或 `storage_key`。 |
| Nginx 直出 | 不建议对 `/data/wecom-bft-new-system/files/` 做公开 `alias`；确需直出时必须使用临时签名 URL 或内部跳转机制，待实现后确认。 |
| 上传大小 | Nginx `client_max_body_size` 与后端 `FILE_MAX_UPLOAD_SIZE_MB` 需要一致。 |

### 6.4 HTTPS 要求

| 场景 | 要求 |
|---|---|
| PC/H5 访问 | 建议全站 HTTPS，避免登录态、Token 和文件下载链接暴露。 |
| 小程序接口 | 必须使用 HTTPS 且域名在微信公众平台配置为合法请求域名。 |
| 企业微信侧边栏 | 必须使用可信 HTTPS 域名，并按企微要求配置可信域名和 JS-SDK 签名域名。 |
| 微信支付/退款回调 | 必须使用公网可达 HTTPS 地址，后端必须校验平台签名。 |
| 物流/发票/企微回调 | 建议统一走 HTTPS `/api/callbacks/**`，按平台要求验签或校验 Token。 |

## 8. Mock、沙箱与真实接入切换

### 8.1 模式定义

| 模式 | 使用场景 | 行为要求 |
|---|---|---|
| `mock` | 本地开发、测试、毕设演示、无真实凭证场景、异常流程验证 | 只替代外部系统，不改变内部领域模型、接口契约、状态机、幂等键和单据结构。 |
| `sandbox` | 外部平台沙箱联调 | 使用沙箱账号、沙箱凭证、沙箱回调地址，仍走统一适配接口和统一回调事件表。 |
| `real` | 真实平台上线接入 | 使用真实平台凭证和公网回调，必须开启签名校验、敏感日志脱敏、幂等和异常补偿。 |

### 8.2 Mock 回调链路

Mock、沙箱和真实平台共用同一组 `/api/callbacks/**` 路径；差异只来自环境模式、适配层、签名校验和回调内容。不得新增仅 Mock 使用的业务回调路径。

| 外部能力 | Mock 行为 | 统一回调路径 | 不允许行为 |
|---|---|---|---|
| Mock 支付 | 生成演示支付流水、事件号、支付结果和支付时间。 | `/api/callbacks/payments/wechat` | 不得直接把订单改为已支付。 |
| Mock 退款 | 生成演示退款流水、事件号、成功或失败原因。 | `/api/callbacks/refunds/wechat` | 不得绕过退款回调直接改退款终态。 |
| Mock 物流 | 生成演示运单号、面单文件引用、轨迹节点、签收事件。 | `/api/callbacks/logistics/traces` | 不得跳过库存和发货单状态校验。 |
| Mock 电子发票 | 生成演示发票号、发票文件引用、税额、失败原因。 | `/api/callbacks/invoices/issue` | 不得绕过发票状态和文件资产。 |
| Mock 红冲 | 生成演示红字发票号、红字发票文件或失败原因。 | `/api/callbacks/invoices/red-reverse` | 不得用红冲替代退款。 |
| Mock 企微审批 | 生成审批通过、拒绝、重复回调或业务状态变化事件。 | `/api/callbacks/wecom/approvals` | 审批模块不得直接修改采购、课程、角色主状态。 |
| Mock 企微通知 | 生成企微卡片发送成功、失败或点击回执。 | `/api/callbacks/wecom/cards` | 通知失败不得回滚主业务。 |
| Mock 邮件/文件发送 | 生成发送受理、发送失败、邮箱错误、文件缺失等结果。 | 可走内部适配结果或后续回调，具体待实现后确认 | 不得改变发票已开具、材料已上传等主状态。 |

### 8.3 从 Mock 切换到沙箱或真实平台

| 步骤 | 操作 | 检查点 |
|---|---|---|
| 1 | 备份当前数据库、上传文件和配置。 | 可在切换失败后恢复演示环境。 |
| 2 | 将目标能力的 `INTEGRATION_*_MODE` 从 `mock` 改为 `sandbox` 或 `real`。 | 支付、退款、物流、发票、企微、邮件可按能力分别切换。 |
| 3 | 填写平台凭证、证书路径、回调 Token、API Key、商户号等服务端配置。 | 不写入前端、不写入文档、不在日志中明文输出。 |
| 4 | 在外部平台登记 HTTPS 回调地址。 | 回调地址必须对应 `/api/callbacks/**`，并能公网访问。 |
| 5 | 重启后端或刷新后台配置。 | Bean 选择、SDK 初始化、证书路径等通常需要重启；后台热切换能力待实现后确认。 |
| 6 | 执行最小沙箱用例。 | 支付下单、支付回调、退款回调、物流轨迹、开票回调至少各走一条。 |
| 7 | 验证回调幂等和异常待处理。 | 重复回调不重复副作用，失败回调进入异常待处理。 |

### 8.4 配置生效方式

| 配置类型 | 示例 | 建议生效方式 | 说明 |
|---|---|---|---|
| 敏感凭证 | 支付私钥、API v3 Key、企微 Secret、发票 API Key、SMTP 密码 | 重启后端生效 | 避免内存中密钥和适配器状态不一致。 |
| 适配器 Bean 选择 | `INTEGRATION_PAYMENT_MODE`、`INTEGRATION_INVOICE_MODE` | 重启后端生效，热切换待实现后确认 | 需防止运行中请求混用新旧适配实现。 |
| Mock 场景 | 下一次支付成功、退款失败、物流乱序、开票失败 | 可后台配置，待实现后确认 | 只控制外部返回结果，不改业务状态机。 |
| 业务阈值 | 采购大额阈值、上传大小、通知模板 | 可后台配置，是否即时生效待实现后确认 | 敏感变更需写操作日志。 |
| 回调公网域名 | `APP_CALLBACK_PUBLIC_BASE_URL` | 通常需重启并同步外部平台配置 | 仅改本地配置不代表平台会回调新地址。 |

## 9. 外部系统回调部署要求

### 9.1 回调入口清单

| 回调类型 | 路径建议 | 关键字段 | 幂等键 | 异常处理 |
|---|---|---|---|---|
| 微信支付回调 | `/api/callbacks/payments/wechat` | `event_no`、`merchant_order_no`、`external_payment_no`、`paid_amount_cent`、`payment_result`、`paid_at`、签名字段 | `source_system + event_no`、`merchant_order_no + external_payment_no` | 金额不一致、已关闭后成功、支付记录缺失进入支付异常待处理。 |
| 微信退款回调 | `/api/callbacks/refunds/wechat` | `event_no`、`refund_no`、`external_refund_no`、`refund_status`、`refunded_amount_cent`、`failure_reason` | `source_system + event_no`、`refund_no + external_refund_no` | `REFUNDED` 终态不被失败覆盖；副作用失败进入补偿。 |
| 物流轨迹回调 | `/api/callbacks/logistics/traces` | `event_no`、`shipment_no`、`tracking_no`、`logistics_node_time`、`node_status`、`signed_flag` | `tracking_no + logistics_node_time + node_status` | 乱序轨迹保留但不回退主状态；签收重复回调幂等。 |
| 电子发票开票回调 | `/api/callbacks/invoices/issue` | `event_no`、`invoice_apply_no`、`invoice_no`、`invoice_file`、`tax_amount_cent`、`status`、`failure_reason` | `source_system + event_no`、`invoice_apply_no + invoice_no` | 自动失败转待开具；发票号重复或文件缺失进入人工核对。 |
| 电子发票红冲回调 | `/api/callbacks/invoices/red-reverse` | `event_no`、`invoice_apply_no`、`red_invoice_no`、`red_invoice_file`、`status`、`failure_reason` | `source_system + event_no`、`invoice_apply_no + red_invoice_no` | 红冲失败保持已开具，支持重试或人工上传凭证。 |
| 企业微信审批回调 | `/api/callbacks/wecom/approvals` | `event_no`、`wecom_approval_id`、`approval_status`、`approval_comment`、`approver_user_id`、`finished_at` | `source_system + event_no`、`wecom_approval_id` | 审批单不存在、业务状态已变化或拒绝原因缺失进入异常补偿。 |
| 企业微信通知卡片回执 | `/api/callbacks/wecom/cards` | `event_no`、`notification_no`、`receiver_user_id`、`send_status`、`failure_reason` | `source_system + event_no`、`notification_no + receiver_user_id + send_status` | 发送失败只记录失败原因，PC 待办兜底，不回滚主业务。 |

### 9.2 回调处理要求

| 要求 | 说明 |
|---|---|
| HTTPS 公网可达 | 真实外部平台必须能访问回调域名；Nginx、防火墙、安全组需放行 443。 |
| 保留原始请求体 | Nginx 代理不得破坏请求体；后端验签通常依赖原始 body、时间戳、随机串和签名头。 |
| 签名校验 | 真实平台必须校验签名、时间戳、防重放参数；Mock 可使用演示签名或内部信任机制，但仍要走回调事件表。 |
| 回调先落库 | 除验签失败外，回调先写 `integration_callback_event`，记录来源、事件号、业务键、处理状态、重试次数和失败原因。 |
| 幂等处理 | 重复事件返回既有处理结果；重复业务结果不重复生成权益、库存流水、发票、通知或审批回写。 |
| 乱序处理 | 成功终态不被失败回调覆盖；低优先级回调写日志或异常摘要。 |
| 失败重试 | 外部平台重试和系统内部重试都必须幂等；可重试失败保留 `retry_count` 和最后失败原因。 |
| 日志脱敏 | 不记录真实密钥、完整签名、完整手机号、税号、地址、私钥、凭证文件正文。 |

## 10. 文件与凭证存储

### 10.1 文件类型与存储策略

| 文件类型 | 业务来源 | 建议存储 Key 模式 | 访问权限 | 备份与清理 |
|---|---|---|---|---|
| 发票文件 | 自动开票回调或人工开票上传 | `invoice/{yyyy}/{MM}/{invoice_apply_no}/{file_no}` | 学员本人、客服只读、代账处理、管理员；按字段脱敏展示 | 交易文件默认不物理删除；随文件存储备份。 |
| 红字发票或红冲凭证 | 自动红冲回调或人工红冲上传 | `invoice-red/{yyyy}/{MM}/{invoice_apply_no}/{file_no}` | 代账、管理员；学员是否可见待业务实现确认 | 不物理删除，错误文件通过失效状态表达。 |
| 退款凭证 | 人工退款登记 | `refund/{yyyy}/{MM}/{refund_no}/{file_no}` | 客服、代账、管理员；学员侧是否展示待实现后确认 | 资金凭证长期保留，下载写审计日志。 |
| 采购进项票 | 供货商 H5 回填或代账补录 | `purchase-input-invoice/{yyyy}/{MM}/{purchase_no}/{file_no}` | 当前供货商、仓管、代账、管理员按业务范围访问 | 采购完成后仍需保留用于代账材料。 |
| 面单文件 | 物流平台返回或仓管上传 | `waybill/{yyyy}/{MM}/{shipment_no}/{file_no}` | 仓管、客服、管理员；学员只看必要物流信息 | 可长期保留；如含地址需下载鉴权。 |
| 对账单导入文件 | 代账上传微信支付账单 | `reconciliation/{bill_month}/{batch_no}/{file_no}` | 代账、管理员 | 与对账批次绑定备份；重复文件按摘要幂等。 |
| 代账材料 | 材料申请上传、系统导出 | `accounting/{yyyy}/{MM}/{material_no}/{file_no}` | 授权代账、材料责任人、管理员 | 月度归档，关闭材料也保留引用。 |
| 导出文件 | 订单、退款、发票、对账、审计导出 | `export/{yyyy}/{MM}/{module}/{file_no}` | 仅导出发起人或授权角色短期访问 | 可设置过期清理，清理策略待实现后确认。 |

### 10.2 文件治理规则

| 规则 | 要求 |
|---|---|
| 文件命名 | 物理存储使用 `file_no`、业务编号和年月分层；展示可保留原始文件名但需安全转义。 |
| 文件资产 | 上传后写入 `sys_file_asset`，包含 `file_no`、`storage_key`、`file_digest`、`file_size`、`biz_type`、`biz_id`、`status`。 |
| 幂等去重 | 使用 `file_digest + biz_type + biz_id` 防止同一业务对象重复绑定相同文件。 |
| 下载鉴权 | 文件下载校验登录态、角色、按钮权限、数据范围、业务对象归属和字段脱敏。 |
| 访问链接 | 不长期保存公开 URL；如对象存储支持临时 URL，应由后端按权限签发。 |
| 备份 | 数据库文件引用和对象存储或本地文件需成组备份，避免恢复后文件引用失效。 |
| 清理 | 交易、退款、发票、对账、审计相关文件默认不物理删除；导出临时文件可按保留期清理，具体保留期待实现后确认。 |

## 11. 日志、监控与排错

### 11.1 日志与监控对象

| 对象 | 落点 | 必看字段 | 用途 |
|---|---|---|---|
| 应用日志 | `/var/log/wecom-bft-new-system/backend/` | `trace_id`、模块、业务编号、状态、错误码、耗时 | 排查接口、业务状态、任务和异常。 |
| Nginx 访问日志 | `/var/log/nginx/wecom-bft-new-system/` | 请求路径、状态码、耗时、上游状态、客户端 IP | 排查 404、502、回调不可达、上传过大。 |
| 回调日志 | `integration_callback_event` + 应用日志 | `source_system`、`event_no`、幂等键、处理状态、重试次数、失败原因 | 排查支付、退款、物流、发票、企微回调。 |
| 操作日志 | `audit_operation_log` | 操作人、角色、IP、模块、动作、目标对象、前后摘要、结果 | 审计退款、发货、开票、红冲、对账、配置和补偿操作。 |
| 异常待处理 | PC 异常聚合入口，数据来自业务状态、回调事件、失败原因和日志 | 异常来源、业务对象、责任角色、可执行动作 | 支持重试、转人工、上传凭证、标记已处理和人工关闭。 |
| 基础监控 | 系统监控或脚本 | CPU、内存、磁盘、进程、端口、证书过期、备份结果 | 避免服务不可用或磁盘打满。 |

### 11.2 常见问题排查

| 问题 | 可能原因 | 排查步骤 | 处理建议 |
|---|---|---|---|
| 服务启动失败 | JDK 版本不兼容、端口占用、环境变量缺失、配置格式错误、数据库不可达 | 查看 systemd/container 日志和应用启动日志；检查 `SERVER_PORT`、数据库、Redis、文件目录权限 | 修正配置后重启；真实密钥不要打印到日志。 |
| 数据库连接失败 | MySQL 未启动、账号密码错误、库名不存在、防火墙阻断、字符集或时区不符合预期 | 用数据库客户端在服务器本机验证连接；检查 `MYSQL_*` 环境变量和 MySQL 用户权限 | 创建数据库和最小权限账号；迁移前先备份。 |
| Redis 连接失败 | Redis 未启动、密码错误、端口不可达、网络策略阻断 | 检查 Redis 进程、端口、密码和应用日志 | 修正 `REDIS_*` 配置；业务事实不得依赖 Redis 恢复。 |
| 回调收不到 | 回调域名未公网解析、HTTPS 证书无效、防火墙未放行、外部平台回调地址配置错误、Nginx 未代理 `/api/callbacks/**` | 用外部网络访问回调健康路径；查看 Nginx 访问日志；核对外部平台回调配置 | 修正 DNS、证书、Nginx、平台配置；确认后端验签错误和网络不可达分开排查。 |
| 回调验签失败 | 原始 body 被改写、Header 未透传、时间戳过期、密钥或证书错误、Mock 签名规则不一致 | 查看回调事件和安全审计摘要；核对 Nginx 是否保留请求体和签名 Header | 修正代理配置和平台凭证；验签失败不得执行业务处理。 |
| Nginx 404 | 静态资源目录错误、SPA 刷新未配置 `try_files`、路径前缀不一致、H5 构建 base 配置错误 | 查看 Nginx error log；核对 `/admin/`、`/h5/**` root 或 alias | 修正静态目录和构建 base；发布后清理旧缓存。 |
| API 502/504 | 后端未启动、端口不一致、上游超时、后端长任务阻塞 | 查看 Nginx upstream 状态和后端健康检查 | 启动后端、调整代理超时、将长任务改异步处理，待实现后确认。 |
| 文件上传失败 | Nginx 上传大小限制、后端大小限制、目录权限、对象存储凭证错误、文件类型不允许 | 查看 Nginx 状态码、后端日志、`sys_file_asset` 是否生成 | 统一 `client_max_body_size` 和后端限制；修正存储权限。 |
| Mock 不生效 | `INTEGRATION_*_MODE` 未设置、配置缓存未刷新、服务未重启、Mock 场景未选、仍调用真实适配器 | 查看启动配置脱敏摘要、系统配置页面、回调事件来源 | 按能力确认模式；需要重启的配置先重启；不要通过改库绕过适配层。 |
| 数据状态不一致 | 回调重复/乱序、补偿任务失败、弱依赖失败、人工操作未记录 | 从订单详情单据链、`integration_callback_event`、异常待处理、审计日志追踪 | 使用补偿入口重试或人工处理；不直接改库。 |

## 12. 备份与恢复

### 12.1 备份策略

| 备份对象 | 建议方式 | 频率 | 注意事项 |
|---|---|---|---|
| MySQL 数据库 | `mysqldump` 或物理备份工具 | 演示前必备份；测试/生产建议每日备份 | 包含业务表、回调事件、审计日志、文件资产引用和配置表。 |
| 上传文件 | 对象存储版本化、桶备份、`rsync` 或归档压缩 | 与数据库备份周期一致 | 文件备份需和数据库中的 `file_no`、`storage_key` 对应。 |
| 配置文件 | `/etc/wecom-bft-new-system/` 归档 | 每次变更前后备份 | 真实密钥备份需加密保存，限制访问。 |
| Nginx 配置和证书引用 | 配置文件归档，证书私钥单独安全保存 | 每次证书或代理配置变更前后备份 | 不把证书私钥提交到仓库。 |
| 演示前快照 | 数据库 + 文件 + 配置 + 当前版本号 | 每次答辩或重要演示前 | 快照命名包含日期、环境和版本号。 |

### 12.2 恢复步骤

| 顺序 | 恢复动作 | 检查点 |
|---|---|---|
| 1 | 停止后端写入流量或进入维护模式。 | 避免恢复过程中产生新订单、回调或文件。 |
| 2 | 备份当前故障现场数据库、文件和日志。 | 即使要回滚，也要保留排障证据。 |
| 3 | 恢复数据库备份。 | 表结构、数据、回调事件、审计日志恢复成功。 |
| 4 | 恢复上传文件或对象存储。 | 抽查发票、退款凭证、面单、对账文件、代账材料可下载。 |
| 5 | 恢复配置文件和 Nginx 配置。 | 域名、证书、代理、环境变量与备份版本一致。 |
| 6 | 启动 MySQL、Redis、MinIO/文件服务、后端、Nginx。 | 健康检查通过，日志无异常。 |
| 7 | 执行一致性检查。 | 订单与支付记录、权益、发货单、发票、文件引用、对账批次一致。 |
| 8 | 恢复外部回调。 | 确认外部平台回调仍指向当前环境；必要时重放未处理回调，必须走幂等链路。 |

| 10 | 退款审核与失败转人工 | PC 管理端 | Mock 退款失败场景 | 客服审核通过后 Mock 退款失败，退款状态为退款失败；可重试或转待人工退款。 |
| 11 | 人工退款或退款成功 | PC 管理端 | 退款单待人工或 Mock 成功场景 | 上传退款凭证后退款状态为已退款，权益冻结或撤销，提醒停止，对账纳入退款。 |
| 12 | 开票与红冲 | 小程序端 + PC 管理端 | 已支付订单，发票抬头完整；另有已开票退款订单 | 学员申请开票；自动或人工开票完成；退款后生成红冲待办，红冲成功后开票状态已红冲。 |
| 13 | 对账导入和差异识别 | PC 管理端 | 预置 Mock 账单文件 | 上传账单，生成已匹配、金额差异、手续费差异、未匹配、重复记录；差异可备注核对。 |
| 14 | 代账材料申请 | PC 管理端 | 代账人员有授权月份 | 发起材料申请，责任人上传文件，代账确认并下载，操作写审计日志。 |
| 15 | 权限切换演示 | PC 管理端 | 已有超管、运营、仓管、客服、代账、讲师账号 | 不同角色看到不同菜单和数据范围；越权接口被后端拒绝。 |
| 16 | 异常待处理和人工补偿 | PC 管理端 | 预置支付金额不一致、权益补开失败、外部已出单内部失败、红冲失败等异常 | 异常聚合展示来源、责任角色、失败原因和动作；可重试、转人工、上传凭证或人工关闭。 |

| 进程检查 | 后端、Nginx、MySQL、Redis、MinIO 或文件服务 | 服务开机自启或可一键恢复，端口无冲突，磁盘空间充足。 |
