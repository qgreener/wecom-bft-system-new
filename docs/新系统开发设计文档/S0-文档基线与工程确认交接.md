## 3. 新系统边界

| 边界项 | 已确认规则 | S1 影响 |
|---|---|---|
| 需求来源 | 需求来自新系统开发设计文档和原型设计方案中的约束/联调文档；原型页面只作为页面展示和交互参考。 | S1 不读取旧代码或旧库结构；如需文档依据，先读 S0 交接和 S1 输入文档。 |
| 旧系统复用 | 只有文档显式标注“参考”或“复用”时才能纳入；当前 S0 未发现允许复用旧实现的授权。 | 禁止从 `wecom-BFT-system-old-failed` 或任何历史工程复制代码、SQL、接口、页面和配置。 |
| 端侧边界 | PC 管理端、小程序端、企微/外部协同端职责分离；企微侧边栏、供货商 H5、公开留资 H5 不作为 PC 一级菜单。 | S1 只建目录和入口骨架，不把协同端混入 PC 管理端。 |
| 订单状态 | 必须拆分为支付、履约、退款、开票四类状态，不设计单一 `order_status`。 | S1 若放置示例类型或占位枚举，必须避免单一订单状态和中文入库状态。 |
| 外部能力 | 支付、退款、物流、开票、企微通知等通过适配层隔离；Mock、沙箱、真实实现共用内部契约和回调链路。 | S1 只建集成分层和配置占位，不接真实平台、不写真实密钥。 |
| 安全配置 | 真实密钥、商户号、私钥、回调地址、SMTP 密码不得入库、入文档、入前端或明文日志。 | S1 `.env.example`、部署模板和配置文件只能使用占位符。 |

## 5. 文档冲突处理规则

| 优先级 | 依据 | 处理规则 |
|---|---|---|
| 1 | `系统设计约束.md` | 优先裁决端侧边界、权限边界、单据链、状态拆分、财税口径和外部接口边界。 |
| 2 | `交互与联调说明.md` | 优先裁决支付、退款、物流、开票、红冲、对账等联调结果和外部触发口径。 |
| 3 | 当前目录编号更靠前的设计文档 | 编号靠前的设计文档约束后续文档，例如模块设计约束数据库和接口设计。 |
| 4 | 三端页面原型文档 | 仅用于确认页面展示、操作入口、字段位置和用户交互。 |
| 5 | 原型 README 概要 | 仅用于确认整体范围，不替代详细设计。 |

| 冲突等级 | 判定标准 | 处理方式 |
|---|---|---|
| 阻断 | 影响 P0、状态机、订单单据链、权限/脱敏、幂等/回调、Mock 正式链路、真实密钥泄露。 | 停止进入依赖阶段，记录冲突和修订建议，先修正或明确裁决。 |
| 可降级 | 只影响低频页面、P1/P2 报表、真实外部接入细节、非 P0 演示增强。 | 可继续当前阶段，但必须在交接中记录修订建议、影响范围和后续处理人。 |
| 待确认 | 优先级规则仍无法裁决，或文档缺少明确口径。 | 标注“待确认”，不直接大改上游文档；在阶段交接中列入修订建议。 |

## 8. 阶段交接格式

| 交接项 | 每阶段必须填写内容 |
|---|---|
| 阶段范围 | 阶段编号、阶段名称、实际执行边界、不做范围。 |
| 输入依据 | 实际读取的文档、上阶段交接记录、临时补充依据。 |
| 修改文件 | 已新增/修改/删除的文件或目录；无代码阶段填写“无”。 |
| 数据库迁移 | Flyway 脚本、seed、迁移验证结果；不涉及时填写“无”。 |
| 接口变化 | 新增/变更接口、路径前缀、通用响应、接口样例；不涉及时填写“无”。 |
| 验证结果 | 执行命令、测试/构建/健康检查结果、失败原因。 |
| 页面证据 | 页面截图、录屏、接口响应样例；无页面阶段填写“无”。 |
| 冲突记录 | 本阶段发现的文档冲突、阻断级别、处理结论。 |
| 修订建议 | 涉及文档、冲突内容、影响范围、建议处理。 |
| 遗留问题 | 未解决依赖、外部条件、降级事项、下一阶段风险。 |
| 下一阶段输入 | 下一阶段应读取的文档、工程目录、验证入口、禁止事项。 |
