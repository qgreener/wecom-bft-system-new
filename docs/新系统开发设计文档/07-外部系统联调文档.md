# 07-外部系统联调文档

## 1. 文档定位

| 项目 | 说明 |
|---|---|
| 文档目标 | 明确新系统与企业微信、微信小程序、微信支付、物流平台、电子发票、邮件或文件发送能力、Mock 外部能力的联调口径 |
| 上游依据 | `00-文档说明.md`、`01-需求规格说明书.md`、`02-业务流程与状态机说明.md`、`03-模块设计文档.md`、`04-领域模型与数据字典.md`、`05-数据库设计文档.md`、`06-API接口文档.md`、当前原型文档 |
| 设计边界 | 本文只写联调说明、状态变化、幂等、失败处理和演示口径，不写真实密钥、真实回调地址、真实商户号、真实企业 ID、真实平台账号和敏感配置 |
| 适用对象 | 后端、前端、测试、部署演示、外部平台联调人员 |
| 核心原则 | 外部能力必须通过统一适配层进入业务模块；Mock、沙箱、真实平台共用同一内部契约、状态枚举、幂等键、`/api/callbacks/**` 回调路径和异常补偿入口 |

## 2. 统一联调原则

| 原则 | 说明 |
|---|---|
| 统一适配层 | 业务模块只依赖支付、退款、物流、开票、企微通知等内部适配接口，不直接依赖平台 SDK、Mock 类或平台特有字段 |
| 统一回调事件 | 支付、退款、物流、开票、红冲、企微审批、企微卡片等外部回调先写入 `integration_callback_event`，再由对应业务模块幂等处理 |
| 统一状态机 | 订单只使用 `payment_status`、`fulfillment_status`、`refund_status`、`invoice_status` 四类状态；Mock 不新增演示专用状态 |
| 统一幂等键 | 外部事件按业务单号、外部流水号、平台事件号组合幂等，重复回调不得重复开通权益、扣减库存、生成通知、开票或红冲 |
| 失败可追溯 | 外部调用失败、回调失败、回调乱序、内部副作用失败必须记录失败原因、原始摘要、重试次数和处理结果 |
| 人工可补偿 | 支付异常、退款失败、外部运单已生成但内部保存失败、自动开票失败、红冲失败、通知发送失败均要有人工补偿入口 |
| 主链路不被弱依赖回滚 | 通知、邮件、企微卡片、订阅消息等发送失败不得回滚支付成功、退款成功、开票成功等主业务状态 |
| 不跨系统原子回滚 | 外部平台已产生支付、退款、运单、发票等结果后，系统不承诺跨系统原子回滚，进入异常待处理和人工补偿 |
| 配置脱敏 | PC 系统设置只允许脱敏展示外部配置，文档、前端页面和日志不得输出明文密钥 |

## 3. 外部系统总览

| 外部系统或能力 | 对接范围 | 主要业务模块 | 主要落库对象 |
|---|---|---|---|
| 企业微信 | 登录、工作台、组织成员、侧边栏、审批、通知卡片 | 用户与权限、线索与学员、通知审批、外部协同、采购供应 | `sys_user`、`crm_lead`、`approval_record`、`notify_message`、`integration_callback_event`、`audit_operation_log` |
| 微信小程序能力 | 小程序登录、手机号授权、订阅消息授权 | 用户与权限、线索与学员、交易订单、通知审批 | `sys_user`、`edu_student`、`notify_message`、`audit_operation_log` |
| 微信支付 | 微信支付下单、支付回调、原路退款、退款回调、账单导入来源 | 交易订单、支付退款、课程与学习、履约库存、发票税务、对账代账 | `trade_order`、`pay_payment`、`pay_refund`、`integration_callback_event`、`finance_reconciliation_record` |
| 物流平台 | 运单、面单、轨迹、费用、签收 | 履约库存、交易订单、对账代账、通知审批 | `fulfillment_shipment`、`logistics_trace`、`inventory_stock_flow`、`acct_material` |
| 电子发票平台 | 自动开票、开票失败回写、红冲、红冲失败回写 | 发票税务、交易订单、对账代账、通知审批 | `tax_invoice`、`tax_invoice_item`、`sys_file_asset`、`integration_callback_event` |
| 邮件或文件发送 | 发票文件发送、发票文件下载、代账材料和导出文件发送 | 发票税务、对账代账、通知审批、系统配置与审计 | `sys_file_asset`、`notify_message`、`acct_material`、`audit_operation_log` |
| Mock 接入 | 本地开发、联调演示、异常流程验证、毕设答辩 | 外部协同、支付退款、履约库存、发票税务、通知审批 | 与真实接入共用正式业务表和 `integration_callback_event` |

## 4. 企业微信联调

### 4.1 联调范围

| 能力 | 说明 |
|---|---|
| 企业微信登录 | PC 网页端支持企业微信扫码登录；企微工作台打开 PC 管理端时不再展示独立登录页 |
| 企业微信工作台 | 作为内部人员进入管理端、审批详情、待办详情和通知卡片落地页的入口 |
| 企微运营侧边栏 | 运营在客户会话中识别外部联系人，查看线索、学员、订单、退款摘要，支持创建线索、匹配线索和写跟进 |
| 企微审批 | 承载角色申请、课程上架/下架、课程删除、大额采购等审批；审批结果回写内部审批单，再由业务模块执行状态流转 |
| 企微通知卡片 | 向审批人、仓管、客服、代账人员等推送待办和风险提醒，点击后进入对应 PC 页面或待办列表 |

### 4.2 联调说明

| 说明项 | 联调口径 |
|---|---|
| 接入目标 | 用企业微信统一内部人员身份入口、工作台入口、审批入口、运营侧边栏入口和内部通知卡片入口，减少系统内重复登录和重复审批页面 |
| 触发场景 | 网页端扫码登录；企微工作台打开管理端；运营打开客户会话侧边栏；未分配角色提交角色申请；课程上架/下架/删除申请；大额采购提交；退款、发货、开票、库存、对账、材料等待办生成 |
| 系统发起动作 | 使用企业微信授权结果识别内部成员并签发管理端登录态；校验企微 JS-SDK 上下文签名并读取 `wecom_external_user_id`；创建或更新 `approval_record`；发送企微通知卡片；为侧边栏提供客户识别、线索建档、跟进记录、学员摘要等接口 |
| 外部回调或返回 | 登录返回企业微信用户身份；侧边栏返回当前外部联系人上下文；审批回调返回审批实例、审批状态、审批意见、审批人和完成时间；卡片回执返回发送、点击或失败结果 |
| 内部状态变化 | `sys_user.wecom_user_id` 绑定内部人员；未分配角色只能进入角色申请；审批状态在 `PENDING`、`APPROVED`、`REJECTED`、`CANCELED` 间变化；审批通过后由业务模块更新课程、采购或角色状态；企微卡片更新 `notify_message.send_status`；侧边栏创建或匹配线索后更新 `crm_lead` 和学员关联 |
| 幂等要求 | `wecom_user_id` 非空唯一；`wecom_external_user_id + mobile + created_date` 或 `Idempotency-Key` 防止侧边栏重复建档；`wecom_approval_id` 非空唯一；`source_system + event_no` 防止审批回调重复；`idempotency_key + channel + receiver_user_id` 防止重复发送同一企微卡片 |
| 失败处理 | 非企业成员、用户禁用、签名校验失败直接拒绝；已登录但无角色时只允许角色申请；侧边栏匹配冲突时标记 `match_exception_flag` 并提示人工确认；审批回调找不到业务对象时记录处理失败；企微卡片发送失败只记录失败原因，不回滚待办或主业务状态 |
| 人工补偿 | 超级管理员可在 PC 管理端处理角色分配、重新触发审批同步或查看审批记录；运营主管可人工匹配外部联系人与线索/学员；待办列表作为企微卡片失败的兜底入口；审批回调失败可由管理员在异常补偿入口重试或关闭并备注原因 |
| 演示 Mock 口径 | 演示环境可提供固定企业微信用户、角色、外部联系人和审批人；扫码登录可由 Mock 授权码换取演示用户；审批支持一键通过/拒绝；企微卡片只生成站内发送记录和模拟回执；侧边栏可选择“已是学员、已是线索、未匹配、匹配冲突”等场景 |

### 4.3 关键校验

| 场景 | 必须校验 | 不允许行为 |
|---|---|---|
| PC 登录 | 企业微信成员身份、用户状态、角色状态 | 非企业成员进入管理端；普通用户绕过角色申请 |
| 工作台入口 | 登录态、角色菜单、数据范围 | 工作台入口绕过 PC 管理端权限矩阵 |
| 侧边栏 | 企微上下文签名、外部联系人 ID、运营数据范围 | 侧边栏直接查看无权限订单、退款和手机号明文 |
| 审批 | 审批人权限、业务对象当前状态、拒绝原因 | 审批模块直接修改业务主状态；重复创建同一待审审批单 |
| 通知卡片 | 接收人企微绑定、场景码、幂等键 | 卡片发送失败后回滚支付、退款、发货、开票等主状态 |

## 5. 微信小程序能力联调

### 5.1 联调范围

| 能力 | 说明 |
|---|---|
| 微信小程序登录 | 首次登录只完成微信身份识别，创建或更新学员基础档案 |
| 手机号授权 | 交易前置能力；未授权手机号不可提交订单、支付、申请退款或申请开票 |
| 学员档案合并 | 同手机号已有学员档案时，自动或人工合并 OpenID 到已有学员 |
| 订阅消息授权 | 仅作为站内通知的补充通道；站内通知才是系统内必达 |

### 5.2 联调说明

| 说明项 | 联调口径 |
|---|---|
| 接入目标 | 用微信身份识别学员，用手机号授权完成交易身份确认，并支撑线索按手机号转化和学员档案合并 |
| 触发场景 | 小程序首次点击微信登录；匿名浏览课程后点击购买；提交订单前未授权手机号；用户维护地址、发票抬头、申请退款或申请开票；用户授权订阅消息 |
| 系统发起动作 | 使用小程序登录凭证换取微信身份摘要；创建或更新 `sys_user`、`edu_student`；手机号授权成功后绑定或合并学员档案；登录态签发 `student_token`；交易接口校验 `mobile_bound=true` |
| 外部回调或返回 | 微信登录返回 OpenID、UnionID 等身份摘要；手机号授权返回手机号解密结果；订阅消息授权返回用户是否同意对应模板 |
| 内部状态变化 | 新学员创建基础档案；已有手机号学员合并 OpenID；学员登录时间更新；交易前置校验通过后可创建订单；支付成功后可按手机号或外部联系人 ID 回写线索为已转化 |
| 幂等要求 | `wx_openid` 非空唯一；`student.mobile` 唯一；`mobile + user_type` 防止重复用户；重复登录只更新登录时间和身份摘要；重复手机号授权返回当前学员或合并后的主档案 |
| 失败处理 | 登录凭证失效、手机号解密失败、手机号冲突且不能自动合并、学员禁用时返回明确错误；拒绝手机号授权时停留当前页面并提示完成授权后可继续购买；订阅消息拒绝不影响站内通知 |
| 人工补偿 | 客服或管理员可在学员管理中处理手机号冲突、合并异常和线索匹配异常；运营可在侧边栏或线索管理中人工关联学员；订阅消息失败通过站内通知兜底 |
| 演示 Mock 口径 | 演示环境提供固定 `wx_openid`、`wx_unionid`、手机号和授权结果；支持模拟首次登录、重复登录、手机号已存在并合并、手机号冲突、拒绝授权；Mock 不绕过交易前手机号授权校验 |

### 5.3 关键校验

| 场景 | 必须校验 | 不允许行为 |
|---|---|---|
| 微信登录 | 登录凭证有效性、学员状态、OpenID 唯一性 | 未登录态访问学员私有订单、退款、发票和通知 |
| 手机号授权 | 手机号格式、手机号唯一性、合并规则 | 未授权手机号创建订单；同手机号生成多份有效主档案 |
| 交易前置 | `mobile_bound=true`、订单归属、学员状态 | 拒绝授权后继续提交订单或拉起支付 |
| 订阅消息 | 用户授权、模板场景、通知幂等键 | 把订阅消息作为唯一通知通道 |

## 6. 微信支付联调

### 6.1 联调范围

| 能力 | 说明 |
|---|---|
| 微信支付下单 | 小程序创建待支付订单后拉起微信支付或 Mock 支付 |
| 支付回调 | 支付平台回调确认成功、失败或异常，驱动订单支付状态和后置动作 |
| 查询补偿 | 支付回调超时、乱序或支付超时后疑似成功时，通过查询或人工核对确认结果 |
| 原路退款 | 客服审核通过且配置支持自动原路退时，调用微信退款 |
| 退款回调 | 退款结果回写退款单并触发退款成功副作用 |

### 6.2 联调说明

| 说明项 | 联调口径 |
|---|---|
| 接入目标 | 支撑小程序订单在线支付、支付成功后置动作、原路退款和退款结果同步，并为收款对账提供商户订单号和外部流水依据 |
| 触发场景 | 小程序提交订单后拉起支付；待支付订单继续支付；支付成功、失败、取消、超时；客服审核通过退款；退款失败后重试；退款失败转人工退款 |
| 系统发起动作 | 创建 `trade_order` 和 `merchant_order_no`；调用支付适配器获取支付参数；接收支付回调并写入 `integration_callback_event`；金额一致后写入 `pay_payment`；发布支付成功事件；审核通过退款时调用退款适配器；接收退款回调并更新 `pay_refund` |
| 外部回调或返回 | 支付下单返回小程序支付参数；支付回调返回平台事件号、商户订单号、外部支付流水、支付金额、支付时间和结果；退款调用返回受理结果；退款回调返回退款单号、外部退款流水、退款金额、退款时间、成功或失败原因 |
| 内部状态变化 | 订单创建后 `payment_status=PENDING`、`refund_status=NONE`、`invoice_status=NOT_APPLIED`；支付成功后 `payment_status=PAID`，生成支付记录、学习权益、站内通知、发货任务和线索转化回写；支付超时或取消后 `payment_status=CLOSED`；退款申请后 `refund_status=REVIEWING`；审核通过后进入 `PROCESSING` 或 `MANUAL_REQUIRED`；退款成功后 `refund_status=REFUNDED` 并冻结或撤销权益、停止提醒、生成红冲待办、纳入对账 |
| 幂等要求 | 创建订单必填 `Idempotency-Key`，建议结合 `student_id + spec_id + client_request_no`；支付回调以 `source_system + event_no`、`merchant_order_no + external_payment_no` 幂等；退款申请以 `order_id + student_id + Idempotency-Key` 幂等；退款回调以 `source_system + event_no`、`refund_no + external_refund_no` 幂等；`REFUNDED` 终态不得被失败回调覆盖 |
| 失败处理 | 支付金额不一致不更新已支付，进入人工核对；支付超时后收到成功回调进入异常待处理，未确认前不自动开放权益；支付后置动作失败不回滚支付成功，生成补偿任务；退款接口超时保持 `PROCESSING` 并查询补偿；退款失败进入 `FAILED`，可重试或转人工；重复和乱序回调按幂等处理 |
| 人工补偿 | 支付记录缺失可补写；权益开通失败由教务/客服补开；发货任务缺失由仓管补建；支付金额异常由财务或代账核对；退款失败可重试或转 `MANUAL_REQUIRED`；人工退款必须登记退款时间、退款渠道、凭证号和凭证文件 |
| 演示 Mock 口径 | Mock 支付必须模拟真实回调链路，不直接改订单状态；支持支付成功、支付失败、用户取消、支付超时后成功、金额不一致、重复回调；Mock 退款支持成功、失败、超时、重复回调、乱序失败回调；Mock 流水使用演示流水号，不写真实商户信息 |

### 6.3 支付成功后置动作

| 后置动作 | 处理口径 | 失败处理 |
|---|---|---|
| 写支付记录 | 保存商户订单号、外部支付流水、金额、支付时间和回调摘要 | 支付记录缺失进入异常待处理并补写 |
| 开通学习权益 | 为订单课程和规格生成 `ACTIVE` 权益 | 权益创建失败重试；重试失败进入教务/客服待处理 |
| 生成发货任务 | 含实物订单生成待发货任务；纯虚拟订单履约为 `NO_SHIPMENT` | 发货任务创建失败生成仓管待办补建 |
| 开放开票入口 | 订单已支付且未申请开票时，小程序展示申请开票 | 不单独回滚 |
| 生成通知 | 站内通知必达；授权后发送订阅消息 | 外部订阅消息失败只记录失败 |
| 线索转化 | 按手机号或外部联系人 ID 匹配线索并回写 `CONVERTED` | 匹配失败记录原因，不影响订单 |
| 对账基础 | 支付记录进入后续账单导入匹配范围 | 上传账单时补算 |

## 7. 物流平台联调

### 7.1 联调范围

| 能力 | 说明 |
|---|---|
| 运单 | 仓管确认发货时获取运单号并保存到发货单 |
| 面单 | 支持不打印、下载面单、云打印三种方式；云打印作为扩展能力 |
| 轨迹 | 订阅或查询运单轨迹，签收时同步订单履约状态 |
| 费用 | 平台返回物流费用时进入物流成本；不返回时由月结账单或人工录入补充 |

### 7.2 联调说明

| 说明项 | 联调口径 |
|---|---|
| 接入目标 | 支撑含实物订单发货、面单获取或打印、物流轨迹查看、签收同步和物流成本归集 |
| 触发场景 | 支付成功后生成待发货任务；仓管在 PC 发货管理点击确认发货；选择快递公司、重量、备注和打印方式；物流平台推送轨迹或签收；代账补录物流费用 |
| 系统发起动作 | 发货前校验订单已支付、履约状态待发货、库存充足、地址快照完整；调用物流适配器创建运单并获取面单数据；按打印方式下载面单或发送云打印命令；保存快递公司、运单号、面单文件；订阅轨迹；扣减 SKU 库存并写库存流水 |
| 外部回调或返回 | 运单接口返回运单号、快递公司编码、面单文件或打印任务结果；轨迹回调返回运单号、节点时间、节点状态、节点描述和签收标识；费用返回运费金额、计费重量或结算摘要 |
| 内部状态变化 | 发货成功后 `fulfillment_shipment.status=SHIPPED`，订单 `fulfillment_status=SHIPPED`，库存扣减并生成出库流水；轨迹回调写入 `logistics_trace`；签收后发货单和订单履约状态变为 `SIGNED`；物流费用进入成本归集或待补录 |
| 幂等要求 | 发货按 `shipment_no` 或 `tracking_no` 幂等；`tracking_no` 非空唯一；物流轨迹以 `tracking_no + logistics_node_time + node_status` 幂等；库存流水以业务幂等键防止重复扣减；签收重复回调不得重复生成副作用 |
| 失败处理 | 运单未产生时，内部履约状态保持待发货且库存不扣减；外部运单、面单或打印结果已产生但内部保存失败时，标记 `exception_flag=true` 并进入异常待处理；面单或云打印失败但运单已保存时可保持已发货并记录打印失败待办；轨迹乱序保留轨迹但不回退主状态；费用未返回时不阻断发货 |
| 人工补偿 | 仓管可在异常待处理中补录运单号、面单文件、快递公司和轨迹；库存异常可通过库存流水人工校正；签收未同步可人工确认签收；物流费用由仓管或代账按月结账单补录 |
| 演示 Mock 口径 | Mock 物流生成演示运单号和面单文件引用，支持下载面单占位文件；轨迹按已揽收、运输中、派送中、已签收时间线模拟回调；支持获取运单失败、外部已生成但内部保存失败、打印失败、费用返回为空、重复轨迹、乱序轨迹 |

### 7.3 发货步骤口径

| 步骤 | 成功结果 | 失败结果 |
|---|---|---|
| 发货前校验 | 已支付、待发货、库存充足、地址完整 | 阻断发货并提示失败原因 |
| 创建运单 | 获得运单号和承运公司 | 未产生运单则保持待发货 |
| 获取面单或打印 | 下载面单、云打印或仅保存运单 | 打印失败记录待办，不必回滚已保存运单 |
| 保存发货信息 | 发货单已发货，订单履约已发货 | 外部已产生结果但内部保存失败，进入异常待处理 |
| 扣减库存 | 写出库库存流水 | 不允许重复扣减；失败进入补偿 |
| 订阅轨迹 | 后续可收到轨迹回调 | 订阅失败可后续重试或人工查询 |

### 8.2 联调说明

| 说明项 | 联调口径 |
|---|---|
| 接入目标 | 支撑订单实付金额开票、电子发票文件回写、退款或开票错误后的红冲处理，并保证未接入或失败时可人工处理 |
| 触发场景 | 学员在小程序提交开票申请；PC 开票管理点击自动开票；未接入电子发票时进入待开具；自动开票失败；退款成功且已开具发票生成红冲待办；代账人员点击红冲 |

| 外部回调或返回 | 开票返回或回调包含发票申请号、发票号码、发票文件、税额、开票时间、成功或失败原因；红冲返回或回调包含原发票申请号、红字发票号码、红字发票文件、红冲时间、成功或失败原因 |
| 内部状态变化 | 学员申请后订单 `invoice_status=APPLIED`；自动开票成功后 `tax_invoice.status=ISSUED`、订单 `invoice_status=ISSUED`，生成站内通知；自动失败或未接入时状态转 `TO_BE_ISSUED` 并生成代账待办；红冲成功后状态转 `RED_REVERSED`；红冲失败保持 `ISSUED` 并记录失败原因 |
| 幂等要求 | 开票回调以 `source_system + event_no`、`invoice_apply_no + invoice_no` 幂等；红冲回调以 `source_system + event_no`、`invoice_apply_no + red_invoice_no` 幂等；同一订单不允许同时存在 `APPLIED`、`TO_BE_ISSUED`、`ISSUED` 正数发票；发票号和红字发票号非空唯一 |
| 失败处理 | 未支付订单拒绝开票；退款中建议阻止新开票；企业抬头缺字段阻断提交；缺税务规则时阻断自动开票和税额统计；自动开票失败转待开具；开票文件回写失败进入异常补偿；红冲失败保留已开具状态并生成可重试待办 |
| 人工补偿 | 代账人员可手动填写发票号码、开票时间并上传发票 PDF 或图片；红冲失败可重试或上传红字发票/处理凭证；订单已退款但未开具时由代账关闭或备注处理；异常补偿入口可重试回调处理 |
| 演示 Mock 口径 | Mock 电子发票支持自动开票成功、自动开票失败、缺税务规则、发票号重复、红冲成功、红冲失败；Mock 发票文件使用演示文件引用；所有结果仍通过统一回调事件处理，不直接改发票状态 |

### 8.3 税务与状态约束

| 约束 | 说明 |
|---|---|
| 发票金额 | 默认等于订单实付金额，不允许学员手动修改 |
| 税务规则 | 自动开票和税额统计必须读取订单课程或规格税务快照 |
| 混合规格 | 按培训服务、教材资料、实物商品、物流等明细拆分后分别计算税额并汇总 |

| 通知边界 | 开票成功通知失败不回滚开票成功 |

## 10. Mock 接入策略

### 10.1 接入目标

| 目标 | 说明 |
|---|---|
| 本地开发 | 在无真实外部账号、沙箱凭证或公网回调条件下完成前后端联调 |
| 异常验证 | 主动模拟失败、超时、重复回调、乱序回调、签名失败、金额不一致、外部已成功但内部失败等场景 |

| 真实切换 | 从 Mock 切换到沙箱或真实接入时，只替换适配实现和环境配置，不重写业务流程 |

### 10.2 联调说明

| 说明项 | 联调口径 |
|---|---|
| 接入目标 | 作为企业微信、微信支付、物流、电子发票、邮件发送等外部能力的替身实现，但不改变内部领域模型、接口契约、状态机、表结构和验收口径 |
| 触发场景 | 开发环境、测试环境、演示环境选择 Mock 模式；测试人员选择成功、失败、超时、重复、乱序、人工处理等场景；部署演示需要无外网或无真实凭证跑通业务闭环 |
| 系统发起动作 | 业务模块仍调用统一适配接口；Mock 适配器返回标准化受理结果；需要异步结果的场景生成 Mock 事件并投递到统一回调处理链路；Mock 场景配置只控制外部返回，不直接修改业务状态 |
| 外部回调或返回 | Mock 支付、退款、物流、开票、红冲、企微审批、企微卡片、邮件发送均返回与真实适配层一致的标准字段；异步场景必须模拟 `event_no`、业务单号、外部流水号、结果状态、失败原因和原始摘要 |
| 内部状态变化 | 与真实平台完全一致：支付成功变 `PAID`，退款成功变 `REFUNDED`，发货变 `SHIPPED`，签收变 `SIGNED`，开票成功变 `ISSUED`，红冲成功变 `RED_REVERSED`；不得增加 Mock 专属状态或临时字段 |
| 幂等要求 | Mock 使用与真实平台相同幂等键，例如 `merchant_order_no + external_payment_no`、`refund_no + external_refund_no`、`tracking_no + logistics_node_time + node_status`、`invoice_apply_no + invoice_no`、`invoice_apply_no + red_invoice_no`、`source_system + event_no` |
| 失败处理 | Mock 必须能模拟平台失败、签名失败、超时、回调丢失、重复回调、乱序回调、金额不一致、发票号重复、运单已产生但内部保存失败等异常；异常处理仍走正式补偿入口 |
| 人工补偿 | 支付异常、退款失败、发货异常、轨迹缺失、开票失败、红冲失败、邮件失败均复用正式人工补偿页面、待办、操作日志和审计记录 |
| 演示 Mock 口径 | 可提供 Mock 场景控制入口或预置演示数据；演示时优先展示成功闭环，再展示失败转人工、重复回调幂等、外部成功内部失败补偿等关键能力；所有演示流水、发票号、运单号、邮箱均使用占位数据 |

| 控制接口 | 联调口径 |
|---|---|
| `GET /api/admin/mock/scenes` | 查询可用 Mock 场景、能力类型、默认参数和启用状态，仅超级管理员或测试授权角色可见 |
| `POST /api/admin/mock/scenes/{scene}/trigger` | 按指定单据触发 Mock 场景并投递到统一回调链路，必须写操作日志和 `integration_callback_event` |

## 11. 联调验收清单

| 企微侧边栏 | 可根据外部联系人展示已是学员、已是线索、未匹配和冲突状态，并支持创建线索、匹配线索、写跟进 |
| 企微审批 | 角色申请、课程审批、大额采购审批可通过、拒绝、重复回调幂等和回写业务状态 |

| 小程序登录和手机号授权 | 未授权手机号不能交易；重复登录和重复授权幂等；同手机号学员合并或进入人工处理 |
| 支付下单 | 订单创建后状态为待支付，具备支付截止时间和商户订单号；继续支付不重复创建订单 |
| 支付回调 | 成功回调将订单置为已支付，生成支付记录、权益、通知和发货任务；重复回调不重复副作用 |
| 退款回调 | 退款成功执行权益、提醒、红冲、履约和对账副作用；失败可重试或转人工；终态不被乱序失败覆盖 |
| 物流联调 | 发货成功保存运单和面单，扣减库存，轨迹更新和签收同步；外部已产生结果但内部失败进入异常待处理 |
| 开票联调 | 自动开票成功保存发票文件并通知；自动失败转待开具；红冲成功转已红冲，红冲失败可补偿 |
| 邮件和文件发送 | 发票文件可保存、发送、失败重试和人工补发；文件下载受权限控制 |
| Mock 切换 | Mock、沙箱、真实接入通过配置切换；Mock 不新增业务状态、不绕过回调和幂等链路 |
| 敏感信息 | 文档、前端页面、日志和演示数据不暴露真实密钥、真实回调地址、真实商户号、真实邮箱凭证和明文敏感配置 |
