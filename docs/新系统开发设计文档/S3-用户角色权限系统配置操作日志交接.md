## 5. 用户角色权限模型

| 层级 | 落点 | 说明 |
|---|---|---|
| 用户 | `sys_user` | PC 内部用户、学员、小程序用户和供货商联系人共用用户主数据；S3 只提供 Mock 登录和后续鉴权边界。 |
| 角色 | `sys_role` | `role_code` 是权限目录主键；`data_scope` 作为数据库侧基础范围口径。 |
| 用户角色 | `sys_user_role` | 管理员审批角色申请后写入或激活授权记录，`grant_status=ACTIVE` 生效。 |
| 权限目录 | `PermissionCatalog` | 后端静态目录合并菜单、按钮权限、数据范围和字段脱敏规则；前端只消费结果，后端接口仍二次校验。 |
| 未分配角色 | `UNASSIGNED` 策略 | 仅返回 `iam:role-application:create`、`role.application` 菜单和 `NONE` 数据范围。 |
| 教务 | `EDU_ADMIN` | `COURSE_ALL` 数据范围；可维护课程规格、查看课节和学习报表；学员手机号默认脱敏。 |
| 讲师 | `TEACHER` | `OWN_COURSE` 数据范围；可维护本人课程课节；样例接口验证本人课程可见、非本人课程禁止。 |

## 6. 权限接口清单

| 接口 | 方法 | 权限 | 说明 |
|---|---|---|---|
| `/api/admin/auth/test-login` | `POST` | 无，测试入口 | 通过 `user_no` 返回 S3 PC 测试令牌。 |
| `/api/admin/auth/wecom-login` | `POST` | 无，Mock 入口 | 接受 `auth_code=mock:<user_no>`，返回同一 PC 管理端令牌，不接真实企微。 |
| `/api/admin/auth/me` | `GET` | 已登录内部用户 | 返回 `roles[]`、`permission_codes[]`、`data_scope`、`menus[]`、`field_masks[]`。 |
| `/api/app/auth/wechat-login` | `POST` | 无，Mock 入口 | 接受 `wx_code=mock:DEMO_APP_STUDENT`，返回 `STU_S3_DEMO` 最小小程序 token。 |
| `/api/supplier-h5/auth/token` | `POST` | 无，Mock 入口 | 接受 `access_token=mock:SUPPLIER_S3` 和 `supplier_no=SUP_S3_DEMO`，返回供货商 H5 session token。 |
| `/api/admin/role-applications` | `POST` | 未分配角色用户 | 提交角色申请，生成 `approval_record`、通知和审计。 |
| `/api/collab/approvals` | `GET` | `iam:role-application:approve` | 查询审批待办，支持 `approval_type`、`status`。 |
| `/api/collab/approvals/{approval_id}/actions` | `POST` | `iam:role-application:approve` | 管理员审批角色申请；通过后写 `sys_user_role` 并审计。 |
| `/api/collab/notifications` | `GET` | 已登录内部用户 | 管理员可查角色申请通知；普通用户只查自身通知；支持 `scene_code`。 |
| `/api/admin/security/scope-samples/{sample_id}` | `GET` | 课程相关权限 | 验证样例数据范围和字段脱敏，讲师只能访问本人课程样例。 |
| `/api/admin/system/configs` | `GET` | 管理员或特定配置只读权限 | 查询配置分组，敏感项仅返回 `masked_value`。 |
| `/api/admin/system/configs` | `POST` | `system:config:write` | 保存配置，敏感项不保存明文，写审计日志。 |
| `/api/admin/audit/logs` | `GET` | `system:audit:read` | 支持按 `trace_id`、`target_type`、`target_id`、`order_id`、操作人和操作类型筛选。 |

## 7. 系统配置与脱敏

| 项目 | 口径 |
|---|---|
| 查询返回 | 只返回 `config_key`、`display_name`、`masked_value`、`editable_flag`、更新时间、更新人和版本，不返回 `plain_value`。 |
| 敏感保存 | `sensitive_flag=1` 的配置保存时统一落 `config_value=<SENSITIVE_SET>`、`masked_value=********`。 |
| 非敏感保存 | 如接入模式、采购阈值、上传限制、Mock 开关可保存原始非敏感值。 |
| 新增配置组 | `PURCHASE`、`FILE`、`NOTIFICATION` 已有最小 seed，可由管理员读取和保存。 |
| 禁止内容 | 未写入真实密钥、商户号、私钥、真实回调地址或 SMTP 密码。 |
| 审计快照 | 配置保存审计只记录配置分组和更新键，不记录敏感配置明文。 |

## 8. 操作日志能力

| 能力 | 落点 |
|---|---|
| 成功写入 | `AuditLogService.writeSuccess` 已接入角色申请提交、角色审批、配置保存。 |
| 失败写入 | `AuditLogService.writeFailure` 已接入权限拒绝、数据范围拒绝、审批状态冲突。 |
| 不可变更 | 未提供编辑或删除接口；审计表沿用 S2 不软删口径。 |
| 查询 | `/api/admin/audit/logs` 支持 `trace_id`、`target_type`、`target_id`、`order_id` 等筛选。 |
| 脱敏 | 审计写入服务会对手机号和密钥类摘要进行兜底脱敏，接口列表不返回前后快照正文。 |
