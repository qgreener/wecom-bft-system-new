## 6.模型说明

| 模型 | 说明 |
|---|---|
| `fulfillment_shipment` | 发货单；承接 S5 支付成功后生成的待发货任务，记录物流公司、物流单号、面单文件、发货/签收时间、异常标记 |
| `fulfillment_shipment_item` | 发货明细；包含主 SKU 和赠品 SKU 行，记录发货数量及对应库存流水 |
| `logistics_trace` | 物流轨迹；按物流单号、节点时间、节点状态幂等写入，支撑重复/乱序回调处理 |
| `inventory_sku` | SKU 基础；记录 SKU 编码、名称、分类、类型、安全库存、默认供货商、当前库存、锁定库存、可用库存 |
| `inventory_stock_flow` | 库存流水；所有库存余额变更必须写流水，含业务类型、业务单据、变更前后库存、幂等键 |
| `purchase_order` | 采购单；记录供货商、总金额、状态、审批、供货商确认/拒绝、采购物流、收货、进项票信息和幂等键 |
| `purchase_order_item` | 采购明细；记录采购 SKU、数量、单价、金额和已收货数量 |
| `purchase_receipt` | 采购入库单；记录收货批次、入库时间、收货人、库存流水集合 |
| `supplier` | 供货商；供货商 H5 通过授权 token 限定自身采购单数据范围 |

## 7.核心规则说明

| 规则 | 实现口径 |
|---|---|
| 发货前置 | 订单必须 `payment_status=PAID`、`fulfillment_status=PENDING_SHIPMENT`、`refund_status` 非 `REFUNDED`，发货单必须 `PENDING_SHIPMENT` |
| 库存扣减 | 发货时先校验主 SKU 与赠品 SKU 全量库存；任一 SKU 不足则阻断，所有 SKU 都不扣减 |
| 库存流水 | 手动入库/出库、发货出库、采购入库都先形成幂等库存流水，再更新 SKU 库存余额，不允许直接改余额 |
| 发货幂等 | `Idempotency-Key` 与发货单状态共同保护；重复发货返回既有发货结果，不重复扣库存或重复生成物流单据 |
| 物流回调 | 物流 Mock 与正式入口统一走 `/api/callbacks/logistics/traces`，先落 `integration_callback_event`，再处理业务轨迹 |
| 重复/乱序轨迹 | 重复轨迹按物流单号、节点时间、节点状态去重；乱序轨迹只追加轨迹，不把 `SIGNED` 回退到 `SHIPPED` |
| 签收 | 管理端签收或回调签收均同步 `fulfillment_shipment.status=SIGNED` 与订单履约状态 `SIGNED` |
| 发货异常 | 库存不足写失败审计；面单失败或外部已出单内部失败保留异常口径，外部已出单内部失败不扣库存、不推进订单履约 |
| 采购创建 | 采购单按 `Idempotency-Key` 幂等创建；大额采购进入 `WAIT_APPROVAL` 并生成审批记录 |
| 采购审批 | 审批通过后采购单进入可供货商确认状态；审批拒绝则不能继续供货商确认和入库 |
| 供货商协同 | 供货商只可处理自身采购单；支持确认接单、拒绝接单、填写采购物流，写操作按幂等键和状态机保护 |
| 采购入库 | 仅已确认/已发采购物流的采购单可收货；收货数量必须与采购明细匹配；重复收货不重复入库 |
| 进项票回填 | 采购完成后可回填进项票号、金额和文件引用；相同内容幂等返回，不同票据冲突 |

## 8.回调先落库与幂等处理

| 场景 | 幂等与落库口径 |
|---|---|
| 物流回调 | `handleLogisticsCallback` 先调用 `CallbackEventRepository.recordReceived` 写 `integration_callback_event`；非 `PENDING` 的重复事件直接返回原处理状态 |
| 物流轨迹 | `logistics_trace` 写入前查询同一 `tracking_no + logistics_node_time + node_status`，已存在则复用，不重复写 |
| 签收终态保护 | 只有当前发货单仍为 `SHIPPED` 时回调签收才推进；已 `SIGNED` 不回退 |
| 采购创建 | `purchase_order.idempotency_key` 唯一索引兜底，重复创建返回既有采购单 |
| 采购入库 | `Idempotency-Key` 与 `purchase_receipt` / `inventory_stock_flow` 共同保护，重复收货返回已有入库结果 |
| 手动库存流水 | `inventory_stock_flow.idempotency_key` 唯一约束保护重复请求 |

## 9.后置动作与单据链

| 动作 | 后置结果 |
|---|---|
| 发货成功 | 发货单进入 `SHIPPED`，订单履约状态进入 `SHIPPED`，发货明细绑定出库库存流水 |
| 签收成功 | 发货单进入 `SIGNED`，订单履约状态进入 `SIGNED` |
| 发货异常 | 写失败审计或异常标记，发货详情可查；异常工作台页面留给后续阶段接入 |
| 采购审批 | 大额采购生成审批记录；审批通过后供货商可确认 |
| 供货商确认/拒绝/填写物流 | 写系统审计，采购单状态按状态机推进或终止 |
| 采购入库 | 采购单进入 `COMPLETED`，采购明细记录已收货数量，库存增加并写入库流水 |
| 单据链 | 发货单、物流轨迹、库存流水、采购单、采购入库通过 `order_document_link` 或详情接口返回的关联对象追溯 |
| 通知/待办 | 本阶段未新增独立通知表任务；异常补偿以审计、异常标记和单据链暴露，供 S7/S8 异常待处理入口接入 |
