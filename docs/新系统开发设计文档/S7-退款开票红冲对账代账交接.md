## 6.模型说明

| 模型 | 说明 |
|---|---|
| `pay_refund` | 退款单；记录申请金额、审核金额、审核人、渠道、外部退款号、人工凭证、失败原因、退款完成时间、权益动作和幂等键 |
| `pay_refund_item` | 退款明细；按订单明细形成退款行，保留课程、规格、数量、金额和快照 |
| `student_invoice_title` | 发票抬头；学员维度保存个人/公司抬头、税号、邮箱、默认标记和幂等键 |
| `tax_invoice` | 发票单与红冲单据承载；记录申请号、订单、抬头、锁定开票金额、开票文件、红冲文件、来源退款和失败原因 |
| `tax_invoice_item` | 发票明细；按订单明细记录开票项目、金额、税率、税额和税务快照 |
| `finance_reconciliation_batch` | 对账批次；按账单月份、来源、文件摘要和幂等键导入，汇总匹配数和差异数 |
| `finance_reconciliation_record` | 对账明细；记录支付/退款匹配结果、系统金额、账单金额、手续费和差异原因 |
| `acct_material` | 代账材料；记录材料类型、月份、关联订单/对象、状态、文件引用、上传/确认/关闭信息和幂等键 |
| `acct_material_relation` | 代账材料关系；连接材料与订单、退款等业务对象，支撑财税工作台追溯 |
| `integration_callback_event` | 外部回调事件；退款、开票、红冲回调先落库再处理业务，保留处理状态、失败原因和幂等键 |
| `order_document_link` | 订单单据链；串联退款单、发票、红冲、代账材料等后置单据 |

## 7.规则说明

| 规则 | 实现口径 |
|---|---|
| 退款申请 | 仅已支付订单可申请；同一订单已有退款审核中、处理中、待人工或已退款时阻断；退款金额不能超过实付金额 |
| 退款审核 | 拒绝后订单 `refund_status=REJECTED` 且权益仍为 `ACTIVE`；原路退款进入 `PROCESSING` 等回调；人工退款进入 `MANUAL_REQUIRED` |
| 审核中不改支付和权益 | 退款申请与审核通过不改 `payment_status`，不调用权益退款副作用，避免提前冻结/撤销 |
| 退款成功 | `REFUNDED` 为终态；重复成功回调不重复副作用；乱序失败回调不覆盖 `REFUNDED` |
| 人工退款 | 人工完成必须提供凭证号和凭证文件引用，完成后共用退款成功副作用 |
| 退款副作用 | 调用 `LearningEntitlementService.applyRefundEffect` 冻结或撤销权益并停止学习提醒；取消待发送提醒；标记待发货或已发货售后异常；已开票订单写 `source_refund_id` 形成红冲待办；创建代账材料；写审计和单据链 |
| 发票抬头 | 学员保存抬头时支持默认标记；公司抬头可记录税号和邮箱；写操作按 `Idempotency-Key` 幂等 |
| 开票申请 | 仅已支付且非退款中/已退款订单可申请；发票金额固定为订单实付金额，不使用前端传入金额 |
| 自动开票 Mock | `/api/callbacks/invoices/issue` 与正式回调同入口；失败转 `TO_BE_ISSUED`，后续可人工开票 |
| 人工开票 | 代账人员上传发票号和文件引用，状态进入 `ISSUED`，订单 `invoice_status=ISSUED`，写单据链 |
| 红冲 | 仅已开票可红冲；红冲完成后状态 `RED_REVERSED`，订单 `invoice_status=RED_REVERSED`；红冲不修改退款状态 |
| 对账导入 | 支付按商户订单号匹配支付单；退款按外部退款号匹配退款单；生成匹配、金额差异、手续费差异、未匹配、重复记录 |
| 对账隔离 | 对账导入只写对账批次和明细，不反向修改 `trade_order`、`pay_payment` 或 `pay_refund` 状态 |
| 代账材料 | 支持待补充、已上传、已确认、已关闭表结构；本阶段接口覆盖创建、上传、确认、下载鉴权和审计 |
| 补偿 | 失败退款可通过协同补偿接口转人工处理；回调失败、红冲失败、文件缺失、对账差异保留失败原因和审计，供后续页面处理 |

## 8.回调先落库与幂等处理

| 场景 | 幂等与落库口径 |
|---|---|
| 退款回调 | `handleWechatRefundCallback` 先调用 `CallbackEventRepository.recordReceived` 写 `integration_callback_event`；重复 `event_no` 直接返回原处理记录 |
| 退款成功副作用 | 退款单终态、权益服务幂等、材料按 `REFUND:{refund_id}` 幂等键创建、单据链 `upsert`，共同避免重复副作用 |
| 退款失败 | 首次失败写 `pay_refund.status=FAILED` 和回调失败原因；如果退款已 `REFUNDED`，失败回调只记事件，不覆盖终态 |
| 开票回调 | `/api/callbacks/invoices/issue` 先落回调事件；失败转 `TO_BE_ISSUED`；成功写发票号、文件和开票时间 |
| 红冲回调 | `/api/callbacks/invoices/red-reverse` 先落回调事件；成功写红冲号、文件和红冲时间；失败保留失败原因 |
| 对账导入 | 批次按 `Idempotency-Key` 与 `bill_month + bill_source + file_digest` 双重幂等；重复账单写 `DUPLICATE` 明细，不中断整个批次 |
| 代账材料 | 创建、上传、确认均要求 `Idempotency-Key`；下载不改业务状态，但写审计 |

## 9.后置动作说明

| 对象 | 后置动作 |
|---|---|
| 权益 | 退款成功后按申请/审核的 `entitlement_action` 冻结或撤销，不重复开通权益 |
| 提醒 | 退款成功后取消订单相关待发送提醒，学习权益 `remind_stopped=1` |
| 履约 | 待发货订单标记发货异常并限制发货；已发货/签收订单标记售后异常，完整售后物流闭环留后续阶段 |
| 库存 | S7 不做逆向库存入库；不重复 S6 发货扣减或采购入库 |
| 发票 | 已开票退款只生成红冲待办口径，红冲由发票红冲流程完成，不替代退款 |
| 对账 | 退款和支付进入对账明细匹配口径；差异只记录，不改交易状态 |
| 代账 | 退款成功自动创建退款代账材料；管理端可申请、上传、确认和鉴权下载材料 |
| 单据链 | 退款、发票、红冲、代账材料通过 `order_document_link` 追溯 |
| 审计 | 退款申请/审核/人工完成、开票、红冲、对账导入、材料创建/上传/确认/下载、补偿重试均写 `audit_operation_log` |

## 15.S8 输入边界

| 输入 | 边界 |
|---|---|
| 后端接口 | S8 可直接使用 S7 已实现的退款、发票、红冲、对账、代账材料接口做页面联调 |
| 权限 | 页面必须沿用后端权限，不可以菜单隐藏替代接口鉴权 |
| 文件 | 发票文件、红冲文件、代账材料文件只传文件引用；下载必须走鉴权接口 |
| 状态机 | 页面不可直接改支付、退款、发票、红冲、对账状态，必须调用 S7 后端接口 |
| Mock | 页面上的 Mock 操作应调用正式回调或正式人工接口，不新增绕过状态机的 Mock 专属接口 |
| 不做 | S8 不得重新处理 S5 支付成功副作用，不重复开通权益、通知或线索转化；不写真实密钥、真实税控账号、真实退款证书或真实回调地址 |
