# 14-工程结构与开发规范

## 1. 文档定位

| 项目 | 说明 |
|---|---|
| 文档目标 | 为新系统落地开发提供仓库结构、后端分层、前端目录、配置、命名、接口、状态、日志、文件、迁移、测试和协作规范 |
| 上游依据 | `00-文档说明.md`、`03-模块设计文档.md`、`05-数据库设计文档.md`、`06-API接口文档.md`、`08-权限矩阵文档.md`、`12-异常处理与幂等补偿设计.md`、`13-技术选型与总体架构设计.md` |

### 2.2 目录职责说明

| 目录 | 职责 | 约束 |
|---|---|---|
| `backend/` | 后端模块化单体工程，承载 API、应用服务、领域规则、持久化、外部适配、任务、审计和补偿 | 不直接依赖前端代码；业务模块不直接依赖平台 SDK 或 Mock 类 |
| `frontend/admin/` | PC 管理端，承载内部角色的菜单、列表、详情、审批、退款、发货、开票、对账、配置和审计 | 前端隐藏按钮只做体验控制，后端必须兜底鉴权 |
| `frontend/h5/wecom-sidebar/` | 企微侧边栏 H5，承载客户识别、线索建档、跟进、学员摘要 | 必须校验企微上下文、内部登录态和运营数据范围 |
| `frontend/h5/supplier/` | 供货商 H5，承载采购确认、拒绝、物流、进项发票回填 | 只能访问当前供货商自身数据 |
| `frontend/h5/lead/` | 公开留资 H5，承载匿名留资、来源码、意向课程 | 需要频率限制、手机号格式校验和来源追踪 |
| `frontend/miniprogram/` | 微信小程序端，承载课程浏览、下单支付、学习、退款、发票、地址、物流和通知 | 小程序不自行确认支付成功，最终状态以后端为准 |
| `frontend/shared/` | 前端共享类型、API 客户端、枚举展示、权限工具、格式化工具 | 类型优先由 OpenAPI 生成，不手写业务状态编码 |
| `database/migration/` | 数据库迁移脚本镜像目录，正式迁移以后端 Flyway 目录为准 | 已执行脚本不得修改，只能新增版本 |
| `database/seed/` | 本地、测试、演示环境初始化数据 | 不放真实账号、真实密钥、真实商户号 |
| `deploy/` | Docker Compose、Nginx、环境模板、部署脚本 | 配置模板只写占位符，不写真实密钥 |
| `docs/` | 开发设计文档、联调文档、验收文档 | Markdown 统一 UTF-8 编码 |
| `scripts/` | 本地启动、格式化、代码生成、迁移辅助脚本 | 脚本必须可重复执行，不直接覆盖生产数据 |
| `tools/` | OpenAPI 生成、Mock 场景、导入模板、开发辅助工具 | 工具输出不得污染正式业务模型 |

## 3. 后端包结构或模块结构

### 3.1 后端工程分层

| 分层 | 推荐包名 | 职责 | 禁止事项 |
|---|---|---|---|
| 接口层 | `interfaces` | Controller、请求响应 DTO、参数校验、统一响应、接口鉴权注解 | 不写状态机；不直接访问数据库；不直接调用外部平台 |
| 应用层 | `application` | 用例编排、事务边界、领域服务调用、事件发布、补偿入口 | 不写平台 SDK 细节；不绕过领域规则直接改状态 |
| 领域层 | `domain` | 领域对象、领域服务、状态机、金额税额规则、领域事件 | 不处理 HTTP、Token、SQL、签名和对象存储细节 |
| 持久化层 | `infrastructure.persistence` | Repository 实现、Mapper、SQL、查询对象、落库 | 不承载业务决策；不调用外部接口 |
| 外部适配层 | `infrastructure.integration` | 企微、微信支付、物流、电子发票、邮件、Mock、沙箱、真实适配 | 不直接修改订单、退款、发货、发票等核心状态 |
| 安全权限层 | `infrastructure.security` | 登录态、Token、角色、按钮权限、数据范围、字段脱敏 | 不把前端菜单隐藏当作最终授权 |
| 文件层 | `infrastructure.file` | 文件资产、对象存储、下载鉴权、摘要校验 | 不把物理路径暴露给前端 |
| 任务层 | `infrastructure.job` | 支付超时、Outbox 重试、回调补偿、异常扫描、通知重试 | 不写不可幂等任务 |
| 共享层 | `shared` | 通用枚举、错误码、金额工具、TraceId、幂等、审计上下文 | 不放具体业务流程 |

### 3.2 业务包划分

| 业务域 | 推荐包名 | 主要对象或能力 |
|---|---|---|
| 用户与权限 | `auth` / `iam` | 用户、角色、菜单、按钮、数据范围、角色申请、登录会话、字段脱敏 |
| 线索与学员 | `crm` / `student` | 线索、跟进、学员档案、手机号合并、企微外部联系人匹配 |
| 课程与学习 | `course` / `learning` | 课程、规格、课节、直播、回放、学习权益 |
| 交易订单 | `trade` / `order` | 订单主单、订单明细、快照、四类摘要状态、单据链 |
| 支付退款 | `payment` / `refund` | 支付记录、支付回调、退款单、人工退款、退款副作用 |
| 履约库存 | `fulfillment` / `inventory` | 发货单、物流、库存 SKU、库存流水、库存预警 |
| 采购供应 | `purchase` / `supplier` | 供货商、采购单、采购审批、收货入库、进项票回填 |
| 发票税务 | `tax` / `invoice` | 发票抬头、开票、红冲、税务规则、销项税 |
| 对账代账 | `finance` / `accounting` | 对账批次、对账明细、差异核对、代账材料、月度报表 |
| 外部协同 | `integration` / `collaboration` | 企微侧边栏、供货商 H5、公开留资、统一回调、外部平台适配 |
| 通知审批 | `notification` / `approval` | 站内通知、订阅消息、企微卡片、审批、待办、异常补偿 |
| 系统配置与审计 | `system` / `audit` | 系统参数、支付配置、物流配置、开票配置、操作日志、审计导出 |

## 4. 前端目录结构

### 4.1 PC 管理端目录

```text
frontend/admin/
├─ src/
│  ├─ app/
│  ├─ assets/
│  ├─ components/
│  ├─ composables/
│  ├─ layouts/
│  ├─ router/
│  ├─ stores/
│  ├─ services/
│  ├─ types/
│  ├─ utils/
│  └─ views/
├─ public/
├─ tests/
├─ vite.config.ts
└─ package.json
```

| 目录 | 职责 | 规范 |
|---|---|---|
| `app/` | 应用初始化、插件注册、全局错误处理 | 不放业务页面 |
| `components/` | 通用组件，如表格、上传、权限按钮、状态标签、文件预览 | 组件命名用 PascalCase |
| `composables/` | 组合式逻辑，如权限、分页、表格筛选、上传、TraceId | 函数命名用 `useXxx` |
| `layouts/` | PC 框架布局、菜单、面包屑、用户信息 | 菜单来自 `/api/admin/auth/me` |
| `router/` | 路由定义和权限守卫 | 路由不硬编码按钮权限 |
| `stores/` | 登录态、权限、枚举字典、系统配置缓存 | 业务事实以后端为准 |
| `services/` | API 客户端、请求拦截器、统一响应处理 | 写操作支持 `Idempotency-Key` |
| `types/` | OpenAPI 生成类型和少量前端扩展类型 | 不重复定义后端枚举 |
| `utils/` | 金额、日期、脱敏展示、文件大小格式化 | 金额展示从分转元，不用浮点参与计算 |
| `views/` | 页面，按一级菜单和业务域组织 | 订单页面必须展示四类状态 |

### 4.2 H5 与小程序目录

| 端侧 | 推荐结构 | 关键要求 |
|---|---|---|
| 企微侧边栏 H5 | `frontend/h5/wecom-sidebar/src/{views,services,components,composables,types}` | 初始化企微 JS-SDK 上下文；接口统一走 `/api/wecom/sidebar/**` |
| 供货商 H5 | `frontend/h5/supplier/src/{views,services,components,composables,types}` | 令牌换取会话；所有请求带供货商 H5 Token；页面不展示其他供货商数据 |
| 公开留资 H5 | `frontend/h5/lead/src/{views,services,components,utils}` | 匿名提交；记录来源码；前端校验不替代后端校验 |
| 小程序端 | `frontend/miniprogram/src/{pages,components,services,stores,utils,types}` | 微信登录、手机号授权、支付、订阅消息按微信小程序能力封装 |
| 共享前端包 | `frontend/shared/{api,enums,formatters,permissions,upload}` | 统一 API 类型、枚举展示、金额格式化、权限判断、上传客户端 |

## 5. 配置文件与环境变量规范

### 5.1 配置文件分层

| 文件 | 适用范围 | 是否提交仓库 | 说明 |
|---|---|---|---|
| `.env.example` | 全仓库 | 是 | 只写变量名和占位符，禁止真实密钥 |
| `.env.local` | 本地开发 | 否 | 开发者本地私有配置 |
| `backend/src/main/resources/application.yml` | 后端通用配置 | 是 | 只放非敏感默认值、结构和占位符 |
| `backend/src/main/resources/application-dev.yml` | 本地开发配置 | 是 | 使用 Mock 模式和本地依赖占位符 |
| `backend/src/main/resources/application-test.yml` | 测试环境配置 | 是 | 使用测试库和测试对象存储占位符 |
| `backend/src/main/resources/application-prod.yml` | 生产配置模板 | 是 | 只放变量引用，不放真实值 |
| `frontend/*/.env.example` | 前端配置模板 | 是 | 只放 API 前缀、环境名、公开配置 |
| `deploy/env/*.example` | 部署配置模板 | 是 | 给 Docker Compose 和 Nginx 使用 |

### 5.2 环境变量命名

| 类别 | 命名规则 | 示例变量 | 说明 |
|---|---|---|---|
| 应用基础 | `APP_` 前缀，大写下划线 | `APP_ENV`、`APP_NAME`、`APP_PUBLIC_BASE_URL` | 环境、应用名、公开访问域名 |
| 应用回调 | `APP_` 前缀，大写下划线 | `APP_CALLBACK_PUBLIC_BASE_URL` | 外部平台回调公网基准地址，用于拼接支付、退款、物流、发票、企微回调 URL |
| 服务端口 | `SERVER_` 前缀 | `SERVER_PORT` | 后端监听端口 |
| 数据库 | `MYSQL_` 前缀 | `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_DATABASE`、`MYSQL_USERNAME`、`MYSQL_PASSWORD` | 密码只从环境变量或密钥管理读取 |
| Redis | `REDIS_` 前缀 | `REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD` | 不把 Redis 当业务事实来源 |
| 文件存储 | `FILE_` 或 `STORAGE_` 前缀 | `FILE_STORAGE_TYPE`、`STORAGE_BUCKET`、`STORAGE_ENDPOINT`、`STORAGE_ACCESS_KEY`、`STORAGE_SECRET_KEY` | 前端不得读取密钥 |
| 集成模式 | `INTEGRATION_` 前缀 | `INTEGRATION_PAYMENT_MODE`、`INTEGRATION_LOGISTICS_MODE`、`INTEGRATION_INVOICE_MODE` | 取值为 `mock`、`sandbox`、`real` |
| 企业微信 | `WECOM_` 前缀 | `WECOM_CORP_ID`、`WECOM_AGENT_ID`、`WECOM_SECRET`、`WECOM_CALLBACK_URL` | 真实密钥不入文档 |
| 微信小程序 | `WECHAT_MP_` 前缀 | `WECHAT_MP_APP_ID`、`WECHAT_MP_SECRET` | 真实密钥只在服务端环境配置 |
| 微信支付 | `WECHAT_PAY_` 前缀 | `WECHAT_PAY_MCH_ID`、`WECHAT_PAY_PRIVATE_KEY_PATH`、`WECHAT_PAY_CALLBACK_URL` | 回调地址按环境配置，不写真实值 |
| 物流 | `LOGISTICS_` 前缀 | `LOGISTICS_PROVIDER`、`LOGISTICS_API_KEY`、`LOGISTICS_CALLBACK_URL` | 按能力维度支持 Mock / 沙箱 / 真实 |
| 电子发票 | `INVOICE_` 前缀 | `INVOICE_PROVIDER`、`INVOICE_API_KEY`、`INVOICE_CALLBACK_URL` | 开票配置脱敏展示 |
| 文件限制 | `FILE_` 前缀 | `FILE_MAX_UPLOAD_SIZE_MB`、`FILE_ALLOWED_TYPES` | 上传大小和类型白名单，前端提示不替代后端校验 |
| 导出保留 | `EXPORT_` 前缀 | `EXPORT_FILE_RETENTION_DAYS` | 导出文件保留期，过期后文件状态失效或清理对象存储 |
| 备份保留 | `BACKUP_` 前缀 | `BACKUP_RETENTION_DAYS`、`BACKUP_STORAGE_PATH` | 数据库和文件备份保留周期与存储位置 |
| 安全 | `SECURITY_` 前缀 | `SECURITY_JWT_SECRET`、`SECURITY_TOKEN_TTL_SECONDS` | JWT Secret 不提交仓库 |

### 5.3 配置使用规则

| 规则 | 要求 |
|---|---|
| 密钥来源 | 真实密钥、商户号私钥、平台 Secret、SMTP 密码只允许来自环境变量、密钥管理系统或服务端安全配置 |
| 前端限制 | 前端只允许使用公开配置，例如 API Base URL、环境名、静态资源域名，不允许出现密钥类变量 |
| Mock 切换 | Mock、沙箱、真实接入通过配置切换，不通过修改业务代码切换 |
| 配置落库 | 数据库配置表只能保存业务配置和脱敏展示值；敏感值保存后不得明文返回 |
| 日志脱敏 | 启动日志、配置变更日志、异常日志不得输出明文密钥、完整手机号、税号、地址、签名原文 |
| 环境隔离 | 本地、测试、演示、生产数据库、Redis、对象存储 Bucket 必须隔离 |

## 6. 命名规范

### 6.1 数据库表名规范

| 规则 | 要求 | 示例 |
|---|---|---|
| 命名风格 | 全部小写蛇形命名 `snake_case` | `trade_order`、`pay_refund` |
| 模块前缀 | 按业务域使用稳定前缀 | `sys_`、`crm_`、`edu_`、`course_`、`trade_`、`pay_`、`fulfillment_`、`inventory_`、`supplier_`、`purchase_`、`tax_`、`finance_`、`acct_`、`notify_`、`approval_`、`integration_`、`audit_` |
| 单复数 | 表名使用业务对象单数或稳定复合名 | `trade_order_item`、`order_document_link` |
| 交易单据 | 不使用临时表表达正式业务状态 | 退款、发票、发货、对账均有正式单据表 |
| 审计日志 | 审计和回调表不软删、不物理删除 | `audit_operation_log`、`integration_callback_event` |

## 7. API 响应格式、分页格式、错误码规范

### 7.1 通用响应格式

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | String | 是 | 业务码，成功为 `OK` |
| `message` | String | 是 | 用户可理解提示 |
| `trace_id` | String | 是 | 链路 ID，对应日志、审计、回调事件 |

| `page` | Object / Null | 分页接口必填 | 分页信息 |

```json
{
  "code": "OK",
  "message": "成功",
  "trace_id": "TRACE_ID_PLACEHOLDER",
  "data": {
    "order_id": 1000000000000000001,
    "order_no": "ORDER_NO_PLACEHOLDER"
  },

}
```

|---|---|---|---|

| `total` | Long | 是 | 总记录数 |
| `pages` | Long | 否 | 总页数，可由后端返回或前端计算 |

```json
    "page_size": 20,

  }

```

### 7.3 HTTP 状态码与业务码

| HTTP 状态码 | 业务含义 | 通用业务码 | 使用场景 |
|---|---|---|---|
| `200` | 成功 | `OK` | 查询、普通动作成功 |
| `201` | 创建成功 | `CREATED` | 创建订单、退款申请、开票申请等 |
| `202` | 已受理 | `ACCEPTED` | 异步处理、通知发送、补偿重试 |
| `204` | 无响应体成功 | `NO_CONTENT` | 标记已读、关闭等无需返回体的动作 |
| `400` | 参数错误 | `INVALID_ARGUMENT` | 参数格式、必填、枚举值错误 |
| `401` | 未登录或回调验签失败 | `UNAUTHORIZED`、`CALLBACK_SIGN_FAILED` | Token 缺失、失效、外部回调签名失败 |
| `403` | 无权限 | `FORBIDDEN` | 角色、按钮、数据范围不允许 |
| `404` | 不存在或无权查看 | `NOT_FOUND` | 对象不存在或隐藏无权对象 |
| `409` | 状态或幂等冲突 | `STATE_CONFLICT`、`DUPLICATE_REQUEST` | 重复提交、状态不允许、幂等参数变化 |
| `422` | 业务规则阻断 | `BUSINESS_RULE_BLOCKED` | 订单未支付不能开票、退款金额超限等 |
| `429` | 频率限制 | `TOO_MANY_REQUESTS` | 留资提交、短信或外部接口调用限流 |
| `500` | 服务端异常 | `INTERNAL_ERROR` | 未预期异常 |

| 类别 | 前缀 | 示例 | 说明 |
|---|---|---|---|
| 通用 | 无前缀或 `COMMON_` | `INVALID_ARGUMENT` | 通用校验、分页、格式错误 |

| 支付退款 | `PAY_` / `REFUND_` | `PAY_AMOUNT_MISMATCH`、`REFUND_IN_PROGRESS` | 支付、退款、人工退款 |

## 8. 状态枚举使用规范，禁止旧状态混用

### 8.1 订单四类状态

| 字段 | 枚举 | 允许值 | 说明 |
|---|---|---|---|
| `payment_status` | `PaymentStatus` | `PENDING`、`PAID`、`CLOSED` | 只表达支付生命周期 |
| `fulfillment_status` | `FulfillmentStatus` | `NO_SHIPMENT`、`PENDING_SHIPMENT`、`SHIPPED`、`SIGNED` | 只表达履约物流生命周期 |
| `refund_status` | `OrderRefundStatus` | `NONE`、`REVIEWING`、`REJECTED`、`PROCESSING`、`MANUAL_REQUIRED`、`FAILED`、`REFUNDED` | 只表达退款摘要状态 |
| `invoice_status` | `OrderInvoiceStatus` | `NOT_APPLIED`、`APPLIED`、`TO_BE_ISSUED`、`ISSUED`、`RED_REVERSED` | 只表达开票摘要状态 |

### 8.2 子单据状态

| 对象 | 字段 | 枚举值要求 |
|---|---|---|
| 支付记录 | `payment_result` | `SUCCESS`、`FAILED`、`PROCESSING`、`CLOSED` |
| 退款单 | `status` | 复用 `OrderRefundStatus`，但不使用 `NONE` |
| 发货单 | `status` | `PENDING_SHIPMENT`、`SHIPPED`、`SIGNED` |
| 学习权益 | `status` | `ACTIVE`、`FROZEN`、`REVOKED` |
| 发票单 | `status` | 复用 `OrderInvoiceStatus`，但不使用 `NOT_APPLIED` |
| 采购单 | `purchase_status` | `APPROVING`、`APPROVAL_REJECTED`、`WAIT_CONFIRM`、`CONFIRMED`、`SHIPPED`、`REJECTED`、`COMPLETED`、`CANCELED` |
| 进项票 | `input_invoice_status` | `NOT_INVOICED`、`INVOICED` |
| 对账结果 | `result` | `MATCHED`、`AMOUNT_DIFF`、`FEE_DIFF`、`UNMATCHED`、`DUPLICATE` |
| 代账材料 | `status` | `PENDING_SUPPLEMENT`、`UPLOADED`、`CONFIRMED`、`CLOSED` |
| 审批 | `status` | `PENDING`、`APPROVED`、`REJECTED`、`CANCELED` |
| 通知发送 | `send_status` | `PENDING`、`SENT`、`FAILED`、`CANCELED` |

### 8.3 状态使用禁令

| 禁止事项 | 说明 |
|---|---|
| 禁止设计单一 `order_status` | 订单必须拆为支付、履约、退款、开票四类状态 |
| 禁止用中文状态入库 | 数据库存英文编码，中文只用于展示 |
| 禁止用数字表达业务枚举 | 除布尔字段外，不使用 `0/1/2` 表达订单、退款、发票、采购等状态 |
| 禁止前端硬编码状态流转 | 前端只做展示和按钮可见性判断，状态合法性由后端状态机控制 |
| 禁止 Mock 增加专属状态 | Mock、沙箱、真实接入共用正式状态枚举 |
| 禁止终态被低优先级回调覆盖 | `PAID`、`REFUNDED`、`ISSUED`、`RED_REVERSED` 等成功终态不被后续失败或乱序回调回退 |
| 禁止混用旧式拼写或混合含义状态 | 不新增未在领域模型和数据库文档确认的旧式状态、复合状态或拼写差异状态 |

## 9. 日志规范

### 9.1 日志分类

| 日志类别 | 主要落点 | 适用场景 | 必填字段 |
|---|---|---|---|
| 业务日志 | 应用日志文件 / 可观测平台 | 关键业务流程排障，如订单创建、支付回调、退款审核、发货、开票 | `trace_id`、模块、业务对象编号、状态、结果、耗时 |
| 操作日志 | `audit_operation_log` | 角色分配、退款、发货、采购、开票、红冲、对账、配置、导入导出、文件上传下载 | 操作人、角色、IP、模块、动作、目标对象、前后快照、结果、失败原因 |
| 回调日志 | `integration_callback_event` | 支付、退款、物流、开票、红冲、企微审批、企微卡片回执 | `source_system`、`event_no`、`event_type`、幂等键、处理状态、重试次数、失败原因 |
| 异常日志 | 应用日志 + 异常待处理聚合 | 未预期异常、外部超时、幂等冲突、状态冲突、副作用失败 | `trace_id`、异常类型、业务对象、错误码、脱敏摘要、处理建议 |
| 文件日志 | `sys_file_asset` + `audit_operation_log` | 发票、红冲凭证、退款凭证、代账材料、导出文件上传下载 | 文件编号、摘要、大小、业务对象、上传人、下载人、权限结果 |

### 9.2 日志脱敏规则

| 敏感数据 | 记录规则 |
|---|---|
| 手机号 | 只记录脱敏值，完整值仅按权限在业务页面展示 |
| 税号、邮箱、地址 | 审计日志只存脱敏值或文件引用 |
| 平台密钥、签名、私钥 | 不写日志、不写数据库明文字段、不写前端 |
| 回调原文 | 保存脱敏摘要到 `raw_snapshot`，不保存完整敏感原文 |
| 文件内容 | 日志只记录文件编号、摘要和存储引用，不记录文件正文 |
| 金额 | 可记录分单位金额，但需关联业务编号和处理结论 |

### 9.3 TraceId 规范

| 场景 | 规则 |
|---|---|
| 请求入口 | 若请求头有 `X-Trace-Id` 则校验后沿用，否则服务端生成 |
| 跨模块调用 | 同一业务用例内保持同一 `trace_id` |
| 回调处理 | 回调事件写入 `integration_callback_event` 时记录 `trace_id` |
| 审计日志 | 敏感操作必须将 `trace_id` 写入 `audit_operation_log` |
| 响应返回 | 所有 API 响应返回 `trace_id`，便于联调排查 |

## 10. 文件上传与存储规范

### 10.1 文件资产模型

| 字段 | 说明 |
|---|---|
| `file_no` | 文件业务编号，对外返回和业务表引用优先使用 |
| `file_name` | 原始文件名，展示时需要安全转义 |
| `file_type` | 文件 MIME 或业务文件类型 |

### 10.2 上传规则

| 项目 | 规范 |
|---|---|
| 上传入口 | 统一走后端文件上传接口，不允许前端直传绕过业务鉴权；如使用直传，也必须由后端签发临时授权 |
| 业务绑定 | 上传后必须绑定 `biz_type + biz_id`，发票、退款凭证、红冲凭证、代账材料、对账账单等必须可追溯到订单或业务对象 |
| 幂等去重 | 使用 `file_digest + biz_type + biz_id` 防止重复绑定同一文件 |
| 类型限制 | 按业务配置允许的 MIME、扩展名、大小限制校验，前端校验不替代后端校验 |
| 病毒与安全 | 可预留病毒扫描、内容类型校验、文件名清洗和下载鉴权 |
| 文件存储 | 推荐 MinIO 或 S3 兼容对象存储；演示环境可本地目录挂载 |
| 下载鉴权 | 文件下载必须校验登录态、角色、数据范围、业务对象和字段脱敏权限 |
| 删除策略 | 交易文件默认不物理删除；错误文件通过状态失效、替换记录和操作日志表达 |

| 新增 JSON 快照 | 必须说明快照来源和敏感字段排除规则 |
| 新增索引 | 必须说明对应查询场景，不为低频查询滥建索引 |
| 数据修复 | 必须可重复执行或有明确幂等条件 |
| 删除字段或表 | P0 阶段原则上不直接删除，先废弃、迁移、验证后再清理 |
| 大表变更 | 需要评估锁表风险，必要时拆分迁移 |

### 11.3 迁移评审清单

| 检查项 | 要求 |
|---|---|
| 状态拆分 | 不出现单一 `order_status` |
| 金额精度 | 不出现浮点金额字段 |
| 幂等唯一键 | 支付、退款、发货、开票、红冲、采购入库、对账导入、通知发送均有唯一键或幂等键 |
| 审计追溯 | 敏感业务表保留创建、更新、版本或操作日志关联 |
| 文件引用 | 文件只存文件编号或存储 key，不存本机绝对路径 |
| 逻辑关联 | 跨模块关联字段有索引，不依赖级联删除 |
| 敏感信息 | 不写真实手机号、税号、密钥、回调地址、商户号、私钥 |

### 13.3 PR 要求

| 项目 | 要求 |
|---|---|
| 标题 | 使用提交规范同类格式，说明模块和目的 |

| 关联文档 | 涉及业务规则、状态、接口、数据库时，必须关联对应设计文档章节 |

| 安全检查 | 确认无真实密钥、无敏感日志、无越权接口 |
| 兼容性 | 说明是否影响已有 API、枚举、前端类型、Mock 场景 |

### 13.4 代码评审清单

| 检查项 | 关注点 |
|---|---|
| 模块边界 | 是否跨模块直接改核心状态，是否绕过应用服务或领域服务 |
| 状态规范 | 是否使用四类订单状态和正式子单据枚举 |
| 幂等与唯一键 | 写接口、回调、导入、通知、文件是否有幂等设计 |
| 权限与脱敏 | 后端是否校验角色、按钮、数据范围和字段脱敏 |
| 日志审计 | 敏感操作、回调、异常、导出是否有日志 |
| 异常补偿 | 外部成功内部失败、超时、重复、乱序是否可追踪可处理 |
| 数据库 | 金额按分、索引合理、交易单据不删除、快照不含密钥 |
| 前端 | 不硬编码状态流转，不绕过权限，不用浮点计算金额 |
| 测试 | 覆盖正常、异常、重复提交、权限、状态冲突和补偿 |

### 14.2 推荐端口

|---|---|---|

### 14.3 启动步骤

| 顺序 | 步骤 | 要求 |
|---|---|---|
| 1 | 复制配置模板 | 从 `.env.example` 复制为 `.env.local`，填写本地占位值，不写真实密钥 |
| 2 | 启动基础设施 | 启动 MySQL、Redis、MinIO，可用 Docker Compose |
| 3 | 执行数据库迁移 | 后端启动时由 Flyway 自动迁移，或手动执行迁移命令 |
| 4 | 初始化种子数据 | 使用本地或演示 seed，创建角色、菜单、Mock 配置、测试课程和测试账号 |
| 5 | 启动后端 | 使用 dev profile，默认外部能力为 `mock` |
| 6 | 启动 PC 管理端 | 连接本地后端 `/api/admin/**` |
| 7 | 启动 H5 页面 | 分别启动企微侧边栏、供货商 H5、公开留资 H5 |
| 8 | 打开小程序 | 微信开发者工具导入 `frontend/miniprogram`，连接本地或内网穿透 API |
| 9 | 验证核心链路 | 登录、创建订单、Mock 支付回调、学习权益、发货、退款、开票、对账导入 |

### 14.4 本地开发约束

| 约束 | 说明 |
|---|---|
| 默认 Mock | 本地默认使用 Mock 支付、退款、物流、开票、企微通知，且必须走正式回调链路 |
| 不改业务代码切环境 | 沙箱或真实接入只改配置，不改应用服务和状态机 |
| 本地数据可重建 | 本地库可清理重建，但迁移脚本和种子数据必须可重复执行 |
| 回调调试 | Mock 回调也走 `/api/callbacks/**`，校验幂等键、事件号和状态机 |
| 日志调试 | 本地日志必须保留 `trace_id`，方便从接口响应追到应用日志、回调事件和审计日志 |
| 文件调试 | 本地文件仍写 `sys_file_asset`，不得直接把本机路径写入业务表 |

### 14.5 部署文件名约定

| 类型 | 约定路径 | 用途 | 说明 |
|---|---|---|---|
| Docker Compose | `deploy/docker-compose.yml` | 服务器默认部署方式，一键启动后端、数据库、Redis、MinIO、Nginx 等依赖 | 最终交付默认采用 |
| 环境模板 | `deploy/env/.env.example`、仓库根 `.env.example` | 提供占位变量和注释，覆盖应用域名、回调地址、上传限制、导出保留、备份保留和外部接入模式 | 不写真实密钥 |
| Nginx 模板 | `deploy/nginx/wecom-bft.conf.template` | 统一入口、静态资源、H5、小程序回调代理和 `/api/**` 转发 | 健康检查可转发 `/api/health` |
| systemd 服务 | `deploy/systemd/wecom-bft.service` | 非容器化服务器部署时托管后端进程 | 仅作为 Docker Compose 不可用时的备选 |
| 部署脚本 | `deploy/scripts/deploy.sh`、`deploy/scripts/rollback.sh`、`deploy/scripts/backup.sh` | 发布、回滚和备份恢复 | 脚本必须幂等，失败时输出可排查日志 |
