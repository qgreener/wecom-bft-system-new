## 2. 总体设计原则

| 原则 | 说明 |
|---|---|
| 订单中心化 | 系统以订单为中心串联线索、学员、支付记录、学习权益、发货单、退款单、发票单、对账记录和代账材料 |
| 状态拆分 | 订单不使用单一订单状态，必须拆分为支付状态、履约状态、退款状态和开票状态 |
| 子单据独立 | 退款、开票、发货、采购等子单据拥有各自状态机，订单只同步摘要状态和单据链入口 |
| 回调幂等 | 支付、退款、物流、开票、红冲等外部回调必须按业务单号、外部流水号或回调事件号做幂等 |
| 副作用可重试 | 支付成功、退款成功、发货成功等主状态变更后的通知、权益、待办、对账等副作用应可重试，不因单个副作用失败回滚主状态 |
| 异常可补偿 | 外部平台已产生结果但内部未完成时，进入异常待处理，由对应角色人工补偿 |
| 财税口径固定 | 发票金额默认等于订单实付金额，红冲只用于已开具发票的冲销，不替代退款 |
| Mock 不分叉 | Mock 支付、退款、物流、开票、红冲必须走真实状态机和回调链路，不新增演示专用状态 |

## 3. 核心单据链

| 顺序 | 单据或对象 | 来源 | 关键状态 | 后续关联 |
|---|---|---|---|---|
| 1 | 线索 | 公开留资 H5、企微侧边栏、PC 运营跟进 | 待跟进、已联系、已转化、已放弃 | 关联学员、订单和转化来源 |
| 2 | 学员 | 小程序微信登录、手机号授权、线索匹配 | 正常档案，不单独承载交易状态 | 关联订单、学习权益、发票抬头和收货地址 |
| 3 | 订单 | 小程序提交订单 | 支付状态、履约状态、退款状态、开票状态 | 关联支付、权益、发货、退款、发票、对账 |
| 4 | 支付记录 | 微信支付或 Mock 支付回调 | 支付成功、支付失败等支付流水结果 | 驱动学习权益、发货任务、对账 |
| 5 | 学习权益 | 支付成功后创建 | 已开通、已冻结、已撤销 | 控制学习中心、课程提醒和课程访问 |
| 6 | 发货单 | 含实物订单支付成功后创建 | 待发货、已发货、已签收 | 关联物流轨迹、库存扣减和物流成本 |
| 7 | 退款单 | 学员申请退款后创建 | 审核中、已拒绝、退款处理中、待人工退款、退款失败、已退款 | 影响权益、提醒、红冲和对账 |
| 8 | 发票单 | 学员申请开票后创建 | 已申请、待开具、已开具、已红冲 | 关联税务规则、发票文件、红冲凭证 |
| 9 | 对账记录 | 上传微信支付结算单/交易账单后生成 | 已匹配、金额差异、手续费差异、未匹配、重复记录 | 进入月度核对和差异导出 |
| 10 | 代账材料 | 代账人员申请或系统汇总生成 | 待补充、已上传、已确认、已关闭 | 支撑收入、退款、采购、开票、税额和成本归集 |

## 4. 核心业务流程

### 4.1 线索转化流程

| 步骤 | 触发端 | 触发动作 | 处理规则 | 输出结果 |
|---|---|---|---|---|
| 1 | 公开留资 H5 | 用户提交姓名、手机号、意向课程 | 校验手机号格式；同手机号重复提交时提示已收到，后台合并来源记录 | 创建或更新线索，来源入口=推广码落地页 |
| 2 | 企微侧边栏 | 运营创建线索或匹配已有线索 | 绑定外部联系人 ID；创建人默认为当前运营 | 创建线索或绑定已有线索 |
| 3 | PC/企微侧边栏 | 运营写跟进 | 保存跟进方式、内容、下次跟进时间 | 线索由待跟进变为已联系 |
| 4 | 小程序 | 学员微信登录并在交易前授权手机号 | 手机号已存在时合并 OpenID 到已有学员档案 | 创建或更新学员 |
| 5 | 小程序/支付回调 | 学员完成支付 | 按手机号或外部联系人 ID 匹配线索；必须存在已支付订单才可转化 | 线索变为已转化，关联学员和订单 |
| 6 | PC | 运营手动确认已转化 | 系统校验已关联学员且存在已支付订单 | 校验通过后线索变为已转化；否则提示不可确认 |

| 异常场景 | 处理口径 |
|---|---|
| 同一手机号多条线索 | 保留多来源记录，优先把订单关联到最近有效线索；后续数据字典可定义主线索标记 |
| 外部联系人 ID 与手机号匹配不同对象 | 标记为待人工核对，不自动覆盖已有关联 |
| 已放弃线索重新沟通 | 允许从详情页重新跟进，状态恢复为已联系 |
| 支付成功但线索匹配失败 | 不影响订单和权益；记录未匹配原因，运营可后续在学员或订单详情中追溯 |

### 4.2 下单支付流程

| 步骤 | 触发端 | 触发动作 | 状态变化 | 关键校验 |
|---|---|---|---|---|
| 1 | 小程序 | 选择课程规格进入订单确认页 | 无状态变化 | 课程已上架，规格有效，价格和税务规则生成订单快照 |
| 2 | 小程序 | 点击提交订单 | 支付状态=待支付；退款状态=无退款；开票状态=未申请 | 必须完成手机号授权；含实物规格必须选择收货地址 |
| 3 | 小程序 | 拉起微信支付或 Mock 支付 | 支付状态保持待支付 | 生成支付截止时间和商户订单号 |
| 4 | 微信支付/Mock | 支付成功回调 | 支付状态=已支付 | 回调验签、金额一致、商户订单号一致、幂等校验 |
| 5 | 小程序 | 支付失败或用户取消 | 支付状态保持待支付 | 未超过支付截止时间可继续支付 |
| 6 | 定时任务/查询补偿 | 支付超时 | 支付状态=已关闭 | 超过支付截止时间且未收到成功支付 |
| 7 | 小程序 | 用户取消待支付订单 | 支付状态=已关闭 | 仅待支付订单允许取消 |

### 4.3 支付成功后置动作

支付成功是订单主链路的关键事件。主状态变为已支付后，以下副作用必须执行，并支持幂等重试。

| 后置动作 | 目标单据或对象 | 处理规则 | 失败处理 |
|---|---|---|---|
| 生成支付记录 | 支付记录 | 保存商户订单号、支付流水号、支付金额、支付时间、支付方式 | 主订单保持已支付；支付记录缺失时进入异常待处理并补写 |
| 开通学习权益 | 学习权益 | 按订单课程、规格、学员创建权益，状态=已开通 | 权益创建失败时重试；重试失败进入教务/客服待处理 |
| 生成发货任务 | 发货单/履约任务 | 含实物订单生成待发货任务；纯虚拟课程履约状态=无需发货 | 发货任务创建失败时记录异常，仓管待办补建 |
| 开放开票申请 | 订单开票状态 | 订单开票状态保持未申请，但小程序展示申请开票入口 | 无需单独回滚 |
| 生成站内通知 | 通知 | 站内通知必达；学员授权订阅消息时同步发送订阅消息 | 订阅消息失败不影响订单，记录发送失败 |
| 线索转化回写 | 线索 | 按手机号或外部联系人 ID 匹配并回写已转化 | 匹配失败不影响订单，记录未匹配原因 |
| 纳入对账范围 | 对账基础数据 | 支付记录进入后续结算单自动匹配范围 | 对账在上传账单时补算 |

### 4.4 学习权益流程

| 权益状态 | 含义 | 可学习 | 进入条件 | 退出条件 |
|---|---|---|---|---|
| 已开通 | 学员已获得课程访问资格 | 是 | 订单支付成功 | 退款成功后冻结或撤销 |
| 已冻结 | 权益暂不可用，但保留恢复或审计依据 | 否 | 退款成功后需要保留学习记录、等待人工确认或业务规则要求冻结 | 人工确认撤销或恢复 |
| 已撤销 | 权益彻底失效 | 否 | 全额退款完成、课程资格应取消 | 只能通过重新购买重新开通 |

| 场景 | 处理口径 |
|---|---|
| 支付成功 | 为订单关联课程创建学习权益，学习中心展示课程入口 |
| 课程直播时间调整 | 已开通权益的学员收到站内通知；授权后发送订阅消息 |
| 课程待删除 | 已购学员提前收到站内通知；授权后发送订阅消息 |
| 退款审核中 | 学习权益暂不变化，避免审核未完成前误伤学员访问 |
| 退款成功 | 按退款规则冻结或撤销学习权益，停止后续课程提醒 |

### 4.5 发货履约流程

| 步骤 | 触发端 | 触发动作 | 状态变化 | 副作用 |
|---|---|---|---|---|
| 1 | 支付成功事件 | 判断订单是否含实物 | 无实物：履约状态=无需发货；含实物：履约状态=待发货 | 含实物生成仓管待发货任务 |
| 2 | PC 发货管理/订单详情 | 仓管确认发货 | 待发货 -> 已发货 | 获取运单号和面单数据，订阅物流轨迹，保存快递公司和单号，扣减 SKU 库存 |
| 3 | 物流平台/Mock | 物流轨迹回调 | 已发货保持不变 | 更新物流轨迹时间线 |
| 4 | 物流平台/Mock | 签收回调或人工确认签收 | 已发货 -> 已签收 | 小程序物流详情展示已签收，订单详情同步履约状态 |
| 5 | 退款成功事件 | 判断实物履约进度 | 状态不新增取消态，发货操作由退款状态控制 | 待发货订单关闭发货任务；已发货/已签收订单进入退货或人工确认 |

### 4.6 退款审核与退款成功副作用

| 步骤 | 触发端 | 触发动作 | 状态变化 | 处理规则 |
|---|---|---|---|---|
| 1 | 小程序 | 学员提交退款申请 | 订单退款状态=审核中；创建退款单=审核中 | 订单支付状态保持已支付 |
| 2 | PC 退款处理 | 客服审核拒绝 | 审核中 -> 已拒绝 | 必填拒绝原因，通知学员 |
| 3 | PC 退款处理 | 客服审核通过且可原路退 | 审核中 -> 退款处理中 | 调用微信支付退款或 Mock 退款 |
| 4 | PC 退款处理 | 客服审核通过但需线下处理 | 审核中 -> 待人工退款 | 财务/代账登记人工退款 |
| 5 | 微信支付/Mock | 原路退款成功回调 | 退款处理中 -> 已退款 | 执行退款成功副作用 |
| 6 | 微信支付/Mock | 原路退款失败回调 | 退款处理中 -> 退款失败 | 可重试或转待人工退款 |
| 7 | PC 退款处理 | 人工退款登记 | 待人工退款 -> 已退款 | 上传凭证，填写退款时间、渠道和凭证号 |

| 退款成功副作用 | 处理口径 |
|---|---|
| 学习权益 | 冻结或撤销订单关联课程权益 |
| 课程提醒 | 停止后续开课提醒、直播时间调整提醒、课程待删除提醒等学员侧通知 |
| 发货履约 | 待发货订单关闭发货操作；已发货或已签收订单判断是否需要退货或人工确认 |
| 发票红冲 | 已开具发票生成红冲待办；未申请或未开具发票不生成红冲 |
| 收款对账 | 退款金额进入微信支付账单核对；对账记录展示退款金额和差异 |
| 代账材料 | 进入退款明细、月度快报和代账导出范围 |
| 通知 | 生成站内退款成功通知；授权订阅消息时同步发送 |

### 4.7 开票与红冲流程

| 步骤 | 触发端 | 触发动作 | 状态变化 | 处理规则 |
|---|---|---|---|---|
| 1 | 小程序 | 学员保存发票抬头 | 无订单状态变化 | 个人抬头无需额外字段；企业抬头校验单位名称和税号 |
| 2 | 小程序 | 学员对已支付未开票订单提交开票申请 | 未申请 -> 已申请 | 发票金额默认订单实付金额，不允许手动修改 |
| 3 | PC 开票管理 | 自动开票成功 | 已申请 -> 已开具 | 生成发票号码、开票时间、发票文件和通知 |
| 4 | PC 开票管理 | 未接入电子发票或自动开票失败 | 已申请 -> 待开具 | 记录失败原因，由代账人员人工处理 |
| 5 | PC/代账工作台 | 人工开票完成 | 待开具 -> 已开具 | 上传发票图片/PDF，填写发票号码和开票时间 |
| 6 | 退款成功/开票错误 | 生成红冲待办 | 已开具保持不变，待办进入处理 | 红冲不能替代退款 |
| 7 | PC/电子发票平台 | 自动红冲或人工上传红字发票完成 | 已开具 -> 已红冲 | 保存红字发票或处理凭证 |

| 税务处理 | 规则 |
|---|---|
| 发票金额 | 默认等于订单实付金额，不允许学员手动修改 |
| 税务规则 | 取订单课程或规格快照中的税务规则 |
| 单一规格 | 税额=含税金额÷(1+税率)×税率 |
| 混合规格 | 按培训服务、教材资料、实物商品、物流等明细拆分后分别计算税额并汇总 |
| 赠品 | 按税务处理方式归入促销成本、随主课开票或单独作为实物赠品处理 |

### 4.8 采购审批与入库流程

| 步骤 | 触发端 | 触发动作 | 状态变化 | 副作用 |
|---|---|---|---|---|
| 1 | PC 采购订单 | 仓管新建采购单 | 小额采购：待确认；大额采购：审批中 | 保存商品明细、数量、单价、总金额和供货商 |
| 2 | 企微审批 | 审批通过 | 审批中 -> 待确认 | 推送供货商 H5 协同消息 |
| 3 | 企微审批 | 审批拒绝 | 审批中 -> 审批拒绝 | 记录拒绝原因并通知申请人 |
| 4 | PC 采购订单 | 取消采购 | 审批中/待确认 -> 已取消 | 已推送供货商的待确认采购需同步取消提示 |
| 5 | 供货商 H5 | 供货商确认接单 | 待确认 -> 已确认 | 保存预计到货日期和备注 |
| 6 | 供货商 H5 | 供货商拒绝接单 | 待确认 -> 已拒绝 | 保存拒绝原因，仓管可重新采购 |
| 7 | 供货商 H5 | 供货商填写物流 | 已确认 -> 已发货 | 保存快递公司和单号 |
| 8 | 供货商 H5 | 供货商填写进项发票 | 采购状态不变，进项发票状态=已开票 | 保存发票号码、金额和文件 |
| 9 | PC 采购订单 | 管理员确认收货 | 已发货 -> 已完成 | 对应 SKU 自动入库，生成入库流水和采购支出记录 |

### 4.9 收款对账流程

| 步骤 | 触发端 | 触发动作 | 处理规则 | 输出结果 |
|---|---|---|---|---|
| 1 | PC 收款对账中心 | 代账人员上传微信支付结算单/交易账单 | 校验文件格式、月份、商户号或账单来源 | 创建对账批次 |
| 2 | 系统 | 按商户订单号匹配订单 | 匹配系统订单、支付记录和退款记录 | 生成对账明细 |
| 3 | 系统 | 比对金额、退款、手续费、到账时间 | 金额一致为已匹配；不一致标记差异原因 | 输出已匹配、金额差异、手续费差异、未匹配、重复记录 |
| 4 | PC 收款对账中心 | 代账人员查看差异 | 可跳转订单、退款和支付记录 | 形成核对备注 |
| 5 | PC 收款对账中心 | 标记已核对 | 记录核对人、核对时间、备注 | 月度对账完成，可导出差异明细 |

| 对账结果 | 含义 | 常见处理 |
|---|---|---|
| 已匹配 | 系统订单与账单记录匹配且金额一致 | 可直接进入月度核对 |
| 金额差异 | 订单金额、结算金额或退款金额不一致 | 查看差异原因，必要时人工核对 |
| 手续费差异 | 手续费与账单记录不一致或缺失 | 可归入差异明细并由代账确认 |
| 未匹配 | 账单有记录但系统无订单，或系统有已支付订单但账单无记录 | 人工核查商户订单号、账期和支付状态 |
| 重复记录 | 同一商户订单号在账单或系统中重复出现 | 标记异常并人工确认有效记录 |

### 4.10 代账材料流转

## 5. 订单状态机

### 5.1 订单状态枚举

订单主记录不设置单一 `order_status`。订单页面、接口和测试用例必须分别处理以下四类状态。

| 状态字段 | 枚举 | 初始值 | 终态 | 说明 |
|---|---|---|---|---|
| 支付状态 `payment_status` | 待支付、已支付、已关闭 | 待支付 | 已支付、已关闭 | 表达订单资金支付结果；退款后仍保持已支付 |
| 履约状态 `fulfillment_status` | 无需发货、待发货、已发货、已签收 | 按商品属性初始化 | 无需发货、已签收 | 表达课程配套实物履约进度 |
| 退款状态 `refund_status` | 无退款、审核中、已拒绝、退款处理中、待人工退款、退款失败、已退款 | 无退款 | 已拒绝、已退款 | 表达订单当前最新退款处理摘要 |
| 开票状态 `invoice_status` | 未申请、已申请、待开具、已开具、已红冲 | 未申请 | 已开具、已红冲 | 表达订单发票申请、开具和红冲结果 |

### 5.2 订单状态流转表

| 场景 | 前置状态 | 触发动作 | 目标状态 | 副作用 |
|---|---|---|---|---|
| 创建订单 | 无 | 小程序提交订单 | 支付=待支付；退款=无退款；开票=未申请；履约=无实物为无需发货、含实物按待发货展示 | 生成订单编号、商户订单号、支付截止时间、价格和税务快照 |
| 继续支付 | 支付=待支付且未超时 | 小程序点击继续支付 | 支付保持待支付 | 重新拉起支付，不重复创建订单 |
| 支付成功 | 支付=待支付 | 微信支付或 Mock 成功回调 | 支付=已支付；无实物履约=无需发货；含实物履约=待发货 | 生成支付记录、学习权益、通知、线索转化回写、发货任务 |
| 支付失败或取消 | 支付=待支付 | 支付失败、用户取消支付 | 支付保持待支付 | 记录失败原因，允许支付截止前继续支付 |
| 支付超时 | 支付=待支付且超过截止时间 | 定时任务或查询补偿 | 支付=已关闭 | 关闭继续支付入口 |
| 用户取消订单 | 支付=待支付 | 小程序确认取消 | 支付=已关闭 | 订单不可继续支付，不生成退款单 |
| 申请退款 | 支付=已支付；退款=无退款/已拒绝/退款失败 | 小程序提交退款申请 | 退款=审核中 | 创建退款单，订单支付状态保持已支付 |
| 退款结果同步 | 存在退款单 | 退款单状态变化 | 订单退款状态同步为退款单最新状态 | 退款成功时执行权益、提醒、红冲、对账等副作用 |
| 申请开票 | 支付=已支付；开票=未申请 | 小程序提交开票申请 | 开票=已申请 | 创建发票单，金额等于订单实付 |
| 开票完成 | 开票=已申请/待开具 | 自动或人工开票成功 | 开票=已开具 | 保存发票文件，通知学员，进入销项税统计 |
| 红冲完成 | 开票=已开具 | 自动或人工红冲完成 | 开票=已红冲 | 保存红字发票或处理凭证 |
| 确认发货 | 支付=已支付；履约=待发货；退款非已退款 | 仓管确认发货 | 履约=已发货 | 获取运单、订阅轨迹、扣减库存 |
| 物流签收 | 履约=已发货 | 物流签收回调或人工确认 | 履约=已签收 | 更新订单物流详情 |

### 5.3 订单异常处理

| 异常场景 | 处理口径 |
|---|---|
| 支付成功回调重复 | 按商户订单号和支付流水号幂等处理，不重复生成权益、发货任务和通知 |
| 支付金额与订单金额不一致 | 不更新为已支付，记录异常支付回调并进入人工核对 |
| 支付超时后收到成功回调 | 以支付平台真实成功为准时需进入人工核对；未确认前不自动开放权益 |
| 待支付订单申请退款或开票 | 拒绝操作，提示订单未支付 |
| 已关闭订单继续支付 | 拒绝拉起支付，提示订单已关闭 |
| 退款中申请开票 | 若未开票，建议阻止新开票申请；若已开票，则等待退款结果后走红冲 |
| 订单子单据副作用失败 | 主状态不回滚，生成异常待处理任务并支持重试 |

## 6. 退款状态机

### 6.1 退款状态枚举

| 状态 | 含义 | 是否终态 | 学员侧展示 |
|---|---|---|---|
| 审核中 | 学员已提交退款申请，等待客服审核 | 否 | 显示审核中 |
| 已拒绝 | 客服拒绝退款申请 | 是 | 显示拒绝原因 |
| 退款处理中 | 已通过审核并发起原路退款 | 否 | 显示预计到账时间 |
| 待人工退款 | 需财务或代账线下处理退款 | 否 | 显示人工处理说明 |
| 退款失败 | 原路退款失败 | 否 | 显示失败原因，等待客服处理 |
| 已退款 | 原路退款成功或人工退款登记完成 | 是 | 显示权益已冻结或撤销 |

订单退款状态额外包含 `无退款`，表示订单当前没有有效退款单。

### 6.2 退款状态流转表

| 起始状态 | 触发动作 | 目标状态 | 触发角色或系统 | 副作用 |
|---|---|---|---|---|
| 无退款 | 学员提交退款申请 | 审核中 | 小程序 | 创建退款单，生成客服待办，订单支付状态保持已支付 |
| 审核中 | 审核拒绝 | 已拒绝 | 客服 | 保存拒绝原因，通知学员，订单退款状态同步已拒绝 |
| 审核中 | 审核通过且配置自动原路退 | 退款处理中 | 客服/系统 | 调用微信支付退款或 Mock 退款 |
| 审核中 | 审核通过但未接入原路退或需线下处理 | 待人工退款 | 客服 | 生成财务/代账人工退款待办 |
| 退款处理中 | 原路退款成功回调 | 已退款 | 微信支付/Mock | 执行退款成功副作用，通知学员 |
| 退款处理中 | 原路退款失败回调 | 退款失败 | 微信支付/Mock | 记录失败原因，可重试或转人工 |
| 退款失败 | 重试退款 | 退款处理中 | 客服/系统 | 再次调用原路退款 |
| 退款失败 | 转人工退款 | 待人工退款 | 客服 | 生成线下处理待办 |
| 待人工退款 | 登记人工退款凭证 | 已退款 | 财务/代账 | 保存退款渠道、退款时间、凭证号和凭证文件 |
| 已拒绝/退款失败 | 学员重新申请 | 新退款单=审核中 | 小程序 | 不复用原退款单，订单退款状态同步最新有效退款单 |

### 6.3 退款异常处理

| 异常场景 | 处理口径 |
|---|---|
| 未支付订单申请退款 | 拒绝申请，提示订单未支付 |
| 重复提交退款申请 | 同一订单存在审核中、退款处理中、待人工退款状态时禁止重复申请 |
| 退款金额超过可退金额 | 拒绝提交或审核，记录校验失败原因 |
| 原路退款接口超时 | 状态保持退款处理中，通过查询接口或人工补偿确认结果 |
| 退款回调重复或乱序 | 按退款单号和外部退款流水幂等；终态已退款不被失败回调覆盖 |
| 人工退款凭证缺失 | 不允许确认已退款 |
| 已开具发票退款成功 | 不阻塞退款，但必须生成红冲待办 |
| 含实物订单退款成功 | 按履约状态判断关闭发货、退货或人工确认，不新增订单履约取消状态 |

## 7. 采购状态机

### 7.1 采购状态枚举

| 状态 | 含义 | 是否终态 | 可见端 |
|---|---|---|---|
| 审批中 | 大额采购已提交，等待企微审批 | 否 | PC、企微审批 |
| 审批拒绝 | 大额采购审批被拒绝 | 是 | PC |
| 待确认 | 采购单已创建或审批通过，等待供货商确认 | 否 | PC、供货商 H5 |
| 已确认 | 供货商已接单并填写预计到货日期 | 否 | PC、供货商 H5 |
| 已发货 | 供货商已填写物流信息 | 否 | PC、供货商 H5 |
| 已拒绝 | 供货商拒绝接单 | 是 | PC、供货商 H5 |
| 已完成 | 管理员确认收货并完成入库 | 是 | PC、供货商 H5 |
| 已取消 | 审批中或待确认采购被取消 | 是 | PC |

采购单另有进项发票状态：`未开票`、`已开票`。进项发票状态不改变采购主状态。

### 7.2 采购状态流转表

| 起始状态 | 触发动作 | 目标状态 | 触发角色或系统 | 副作用 |
|---|---|---|---|---|
| 无 | 新建小额采购单 | 待确认 | 仓管 | 推送供货商 H5 协同消息 |
| 无 | 新建大额采购单 | 审批中 | 仓管 | 生成企微审批待办 |
| 审批中 | 审批通过 | 待确认 | 审批人 | 推送供货商，记录审批日志 |
| 审批中 | 审批拒绝 | 审批拒绝 | 审批人 | 保存拒绝原因，通知申请人 |
| 审批中/待确认 | 取消采购 | 已取消 | 仓管/管理员 | 记录取消原因；若已通知供货商则同步取消提示 |
| 待确认 | 供货商确认接单 | 已确认 | 供货商 H5 | 保存预计到货日期和备注 |
| 待确认 | 供货商拒绝接单 | 已拒绝 | 供货商 H5 | 保存拒绝原因，仓管可重新发起采购 |
| 已确认 | 供货商填写物流 | 已发货 | 供货商 H5 | 保存快递公司、快递单号 |
| 已发货 | 管理员确认收货 | 已完成 | 仓管/管理员 | SKU 自动入库，生成入库流水、采购支出记录 |
| 已发货/已完成 | 供货商上传进项发票 | 主状态不变，发票状态=已开票 | 供货商 H5 | 保存发票号码、发票金额、发票文件，进入进项票归集 |

### 7.3 采购异常处理

| 异常场景 | 处理口径 |
|---|---|
| 审批中采购推送供货商 | 禁止推送，审批通过后才可推送 |
| 审批拒绝后再次采购 | 原采购单终止，需新建采购单 |
| 供货商长时间未确认 | 生成采购待确认提醒，仓管可催办或取消 |
| 供货商拒绝接单 | 原采购单终止，仓管重新选择供货商或调整采购 |
| 已确认后取消 | 默认不允许直接取消；确需取消应走人工备注和操作日志 |
| 收货数量与采购数量不一致 | 不自动完成入库，进入人工确认；后续可在库存流水记录实际入库数量 |
| 重复确认收货 | 按采购单号幂等，不重复入库 |
| 进项发票缺失 | 不阻塞采购完成，但进入代账“采购无进项票”风险提醒 |

## 8. 开票状态机

### 8.1 开票状态枚举

| 状态 | 含义 | 是否终态 | 说明 |
|---|---|---|---|
| 未申请 | 已支付订单尚未提交开票申请 | 否 | 订单级状态，尚未生成发票单 |
| 已申请 | 学员已提交开票申请，等待自动或人工开票 | 否 | 发票金额锁定为订单实付金额 |
| 待开具 | 未接入电子发票或自动开票失败，等待人工开具 | 否 | 必须记录失败原因或人工处理原因 |
| 已开具 | 发票已开具并保存文件或号码 | 是 | 可进入红冲处理 |
| 已红冲 | 已开具发票完成红冲 | 是 | 保存红字发票或处理凭证 |

### 8.2 开票状态流转表

| 起始状态 | 触发动作 | 目标状态 | 触发角色或系统 | 副作用 |
|---|---|---|---|---|
| 未申请 | 学员提交开票申请 | 已申请 | 小程序 | 创建发票单，锁定抬头、邮箱、金额、税务规则快照 |
| 已申请 | 自动开票成功 | 已开具 | 电子发票平台/Mock | 保存发票号码、文件、开票时间，通知学员，进入销项税统计 |
| 已申请 | 未接入电子发票 | 待开具 | 系统 | 禁用自动开票，生成代账人工开票待办 |
| 已申请 | 自动开票失败 | 待开具 | 电子发票平台/Mock | 记录失败原因，生成代账人工开票待办 |
| 待开具 | 人工开票完成 | 已开具 | 代账人员 | 保存发票号码、开票时间、发票文件，通知学员 |
| 已开具 | 退款成功或开票错误，红冲完成 | 已红冲 | 电子发票平台/代账人员 | 保存红字发票或处理凭证，进入红冲汇总 |

### 8.3 开票异常处理

| 异常场景 | 处理口径 |
|---|---|
| 未支付订单申请开票 | 拒绝申请，提示订单未支付 |
| 学员修改发票金额 | 不允许，金额只读并等于订单实付金额 |
| 企业抬头缺少单位名称或税号 | 阻止提交并提示补全 |
| 课程或规格缺少税务规则 | 不影响人工开票申请，但自动开票和税额统计应阻止并提示配置税务规则 |
| 自动开票失败 | 转为待开具，记录失败原因，由代账人员人工开具 |
| 重复提交开票申请 | 同一订单已申请、待开具或已开具时禁止重复申请 |
| 退款发生在未开具前 | 若退款已成功，原则上不再允许开具正数发票；若已申请未开具，应由代账关闭或备注处理 |
| 退款发生在已开具后 | 生成红冲待办，红冲完成后状态变为已红冲 |
| 红冲失败 | 发票状态保持已开具，红冲待办标记失败原因并支持重试或人工上传凭证 |

### 9.2 履约状态流转表

| 起始状态 | 触发动作 | 目标状态 | 触发角色或系统 | 副作用 |
|---|---|---|---|---|
| 无 | 创建无实物订单 | 无需发货 | 小程序/系统 | 不生成发货任务 |
| 无/展示待发货 | 含实物订单支付成功 | 待发货 | 支付成功事件 | 生成发货任务和仓管待办 |
| 待发货 | 确认发货成功 | 已发货 | 仓管/物流平台 | 保存运单号、面单数据、发货时间、发货人，扣减 SKU 库存，订阅物流轨迹 |
| 已发货 | 物流轨迹更新 | 已发货 | 物流平台/Mock | 更新物流详情，不改变主履约状态 |
| 已发货 | 物流签收 | 已签收 | 物流平台/Mock/人工 | 同步订单履约状态，物流详情展示签收节点 |

### 9.3 履约异常处理

| 异常场景 | 处理口径 |
|---|---|
| 含实物订单缺少收货地址 | 提交订单前阻断，要求选择或新增地址 |
| 支付未成功就发货 | 禁止发货，发货入口只对已支付且待发货订单展示 |
| 退款已成功的待发货订单 | 禁止继续发货；关闭发货任务，履约状态保持追溯口径，操作可用性由退款状态控制 |
| 库存不足 | 发货前校验库存；不足时阻断发货并生成库存预警或采购建议 |
| 物流平台获取运单失败 | 履约状态保持待发货，库存不扣减，提示失败原因 |
| 外部运单已生成但内部保存失败 | 进入异常待处理，由仓管人工补偿；不得静默丢失外部运单 |
| 面单或云打印失败 | 若运单已保存，可保持已发货并记录打印失败待办；若内部发货未完成，则按异常待处理 |
| 重复发货 | 按发货单或订单号幂等，不允许重复扣减库存 |
| 物流签收回调重复 | 幂等处理，已签收不重复生成副作用 |
| 已发货或已签收后退款 | 退款流程进入退货或人工确认，不新增履约状态 |

## 10. 跨流程触发动作与副作用矩阵

| 触发事件 | 必须动作 | 可延迟或可重试动作 | 不应发生的动作 |
|---|---|---|---|
| 支付成功 | 订单支付状态变为已支付；生成支付记录；开通学习权益 | 生成通知、线索转化、发货任务、对账基础数据 | 不因通知失败回滚支付状态 |
| 支付超时 | 支付状态变为已关闭 | 清理待支付提醒 | 不生成退款单 |
| 提交退款申请 | 创建退款单；订单退款状态=审核中 | 通知客服待审核 | 不改变支付状态和学习权益 |
| 退款拒绝 | 退款状态=已拒绝 | 通知学员 | 不关闭学习权益 |
| 退款成功 | 退款状态=已退款；权益冻结或撤销；停止提醒 | 红冲待办、退货确认、对账和代账同步 | 不把支付状态改为已关闭 |
| 发货成功 | 履约状态=已发货；保存物流信息；扣减库存 | 轨迹订阅、物流成本补录 | 不对未支付订单发货 |
| 签收成功 | 履约状态=已签收 | 通知或报表更新 | 不改变退款状态 |
| 开票成功 | 开票状态=已开具；保存发票文件 | 通知学员、销项税汇总 | 不修改订单实付金额 |
| 红冲成功 | 开票状态=已红冲 | 红冲汇总、代账材料同步 | 不替代退款流程 |
| 采购完成 | 采购状态=已完成；SKU 入库 | 采购支出、进项票提醒 | 不重复入库 |
| 对账完成 | 记录核对人、时间、备注 | 导出差异、月度归档 | 不反向修改支付真实流水 |

## 11. 通用幂等与补偿规则

| 场景 | 幂等键 | 补偿入口 | 说明 |
|---|---|---|---|
| 支付回调 | 商户订单号 + 支付流水号 | 订单异常待处理、支付记录补写 | 重复成功回调不重复开通权益 |
| 退款回调 | 退款单号 + 外部退款流水号 | 退款失败重试、转人工退款 | 已退款终态不被失败回调覆盖 |
| 物流回调 | 运单号 + 物流节点时间 | 发货异常待处理、人工补录轨迹 | 重复轨迹不重复写入 |
| 开票回调 | 发票申请号 + 发票号码 | 待开具人工处理 | 自动失败转待开具 |
| 红冲回调 | 发票单号 + 红字发票号码 | 红冲待办重试、人工上传凭证 | 红冲完成后不再重复处理 |
| 采购入库 | 采购单号 + 入库批次 | 库存流水人工校正 | 防止重复确认收货导致重复入库 |
| 对账导入 | 账单月份 + 文件摘要 | 对账批次重跑 | 防止重复上传生成重复对账记录 |

## 12. 验收关注点

| 验收项 | 通过标准 |
|---|---|
| 状态拆分 | 订单列表、订单详情、接口和测试均分别展示支付、履约、退款、开票状态 |
| 支付后置动作 | 支付成功后可看到支付记录、学习权益、通知；含实物订单进入待发货 |
| 线索转化 | 公开留资或侧边栏线索能在同手机号支付成功后回写已转化 |
| 学习权益 | 已支付订单可学习；退款成功后权益冻结或撤销，提醒停止 |
| 发货履约 | 待发货、已发货、已签收状态可流转，发货成功扣减库存 |
| 退款闭环 | 审核拒绝、自动退款、人工退款、退款失败重试、退款成功副作用均可演示 |
| 开票红冲 | 已支付订单可申请开票；自动失败可人工开票；已开具退款可红冲 |
| 采购入库 | 大额采购先审批，通过后推送供货商，确认收货后自动入库 |
| 收款对账 | 上传账单后可识别已匹配、金额差异、手续费差异、未匹配和重复记录 |
| 代账材料 | 代账人员可申请补充材料，管理员上传后代账可确认和下载 |
| 异常补偿 | 支付、退款、物流、开票、红冲等外部异常均有失败原因、重试或人工处理入口 |
