# 系统设计约束

说明：本文记录界面方案需要遵守的系统边界和约束，避免把权限、安全、外部接口和数据口径细节混写在界面原型里。

## 1.端侧边界

| 端 | 范围 |
|---|---|
| PC 管理端 | 后台角色处理业务、财税、库存、报表和配置 |
| 小程序端 | 学员浏览课程、下单支付、学习、申请退款和发票 |
| 企微/外部协同端 | 企微侧边栏、供货商 H5、审批消息、企微通知卡片、公开留资 H5 |

## 2.导航约束

PC 管理端采用一级分组 + 二级菜单，低频配置项默认收纳在系统配置中，避免左侧菜单过长。

| 一级菜单 | 二级菜单 |
|---|---|
| 首页 | 数据概览、角色流程看板 |
| 客户与学员 | 线索管理、学员管理 |
| 课程与履约 | 课程管理、课程编辑页 |
| 供应与库存 | 库存管理、供货商管理、采购订单、发货管理 |
| 交易售后 | 订单管理、退款处理、开票管理 |
| 财税与报表 | 数据报表、代账管理、收款对账中心 |
| 系统配置 | 物流配置、税务规则、操作日志、系统设置 |

## 3.权限约束

1. 用户实际看到的菜单由角色和可见模块共同决定。
2. 企微侧边栏、供货商 H5 和公开留资 H5 不作为 PC 管理端一级菜单。
3. 操作日志仅管理员常用，默认收纳在系统配置下。
4. 物流配置和操作日志属于低频配置，默认折叠。
5. 代账人员进入 PC 管理端，但仅能访问被授权的财税与代账模块。
6. 本期取消外部平台订单设计，不设计微信小店、抖店等外部销售渠道的订单同步、渠道配置和商品映射。

## 4.单据链约束

系统以订单为中心串联业务单据：

线索 → 学员 → 订单 → 支付记录 → 学习权益/发货单 → 退款单 → 发票单 → 收款对账 → 代账材料/代账汇总

界面上应在订单详情页保留单据链入口，使业务、财务、税务相关记录可追溯。

## 5.状态口径约束

1. 订单不使用单一状态承载全流程，统一拆分为支付状态、履约状态、退款状态和开票状态。
2. 支付状态包括：待支付、已支付、已关闭。
3. 履约状态包括：无需发货、待发货、已发货、已签收。
4. 退款状态包括：无退款、审核中、已拒绝、退款处理中、待人工退款、退款失败、已退款。
5. 开票状态包括：未申请、已申请、待开具、已开具、已红冲。
6. 支付成功后必须生成支付记录和学习权益；含实物订单生成待发货任务；订单进入可申请开票状态；通知和线索转化回写按联调说明执行。
7. 退款成功后必须处理副作用：冻结或撤销学习权益、停止后续提醒、已开票订单生成红冲待办、含实物订单判断是否退货或人工确认。
8. 大额采购先进入审批中，审批通过后才进入待确认并推送供货商，审批拒绝后进入审批拒绝。

## 6.财税口径约束

1. 发票金额默认等于订单实付金额，不允许学员手动修改。
2. 课程或规格必须绑定税务规则后，才能用于接入电子发票后的自动开票和税额统计。
3. 税务规则包含开票内容、税率、适用课程/规格、税务处理方式和启用状态，原则上由代账人员维护。
4. 红冲只用于已开具发票的冲销处理，不能直接替代退款。
5. 成本归集可先支持手动录入和文件导入，不要求一开始自动采集全部成本。
6. 发票税额按订单课程/规格快照中的税务规则计算，含税金额拆分口径为：税额=含税金额÷(1+税率)×税率。
7. 混合规格需在课程规格内配置金额拆分，例如培训服务、教材资料、实物商品、物流分别对应不同税务规则，系统按明细分别计算税额后汇总。
8. 赠品需配置税务处理方式：可作为促销成本、随主课开票，或按实物赠品单独处理。
9. 税负率、财税预测和经营建议仅作经营参考，不作正式税务申报依据。

## 7.外部接口约束

1. 界面原型不写具体接口地址、请求参数、密钥和回调地址。
2. 接口名称、鉴权、签名、回调、幂等等内容放入后续接口或联调文档。
3. 第三方平台能力可先按演示口径设计界面，但必须保留成功、失败和人工处理入口。
4. 直播状态由外部回调或人工同步，不在后台承诺直接控制企微直播开播/结束。
5. 外部物流、打印、电子发票等接口失败时，内部状态可回滚；外部已产生结果的情况进入异常待处理和人工补偿，不承诺跨系统一致回滚。
