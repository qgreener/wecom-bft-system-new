# 交互与联调说明

说明：本文承接界面原型中不适合展开的联调约定、外部系统触发点和状态同步口径。界面文档只描述用户看到什么、能点什么；本文描述点击后需要与外部系统或后端协作的关键结果。

## 1.审批联动

| 场景 | 界面触发 | 联调结果 |
|---|---|---|
| 角色申请 | 未分配角色用户提交申请 | 生成审批待办，审批通过后分配角色，审批拒绝后通知申请人 |
| 课程上架/下架 | 课程管理点击申请上架/申请下架 | 生成审批待办，审批通过后更新课程状态 |
| 课程删除 | 课程管理提交删除申请 | 审批通过后课程进入待删除，先生成已购学员站内通知；学员授权订阅消息时同步发送，3天后正式删除 |
| 大额采购 | 新建采购单金额超过阈值 | 采购单先进入审批中；审批通过后状态变为待确认并推送供货商，审批拒绝后状态变为审批拒绝 |

## 2.企微与外部协同

| 场景 | 页面位置 | 联调约定 |
|---|---|---|
| 企微运营侧边栏 | 企微/外部协同端 | 根据当前聊天对象匹配学员或线索，支持写跟进、创建线索、匹配线索 |
| 供货商 H5 | 企微/外部协同端 | 供货商确认接单、拒绝、填写物流和进项发票后，PC 管理端同步状态 |
| 企微通知卡片 | 企微/外部协同端 | 系统待办和风险预警通过卡片进入对应 PC 页面 |
| 公开留资 H5 | 企微/外部协同端 | 用户提交表单后创建线索，来源记录为落地页 |

## 3.支付与退款

| 场景 | 联调约定 |
|---|---|
| 订单状态口径 | 订单不再使用单一状态承载全流程，拆为支付状态（待支付/已支付/已关闭）、履约状态（无需发货/待发货/已发货/已签收）、退款状态（无退款/审核中/已拒绝/退款处理中/待人工退款/退款失败/已退款）、开票状态（未申请/已申请/待开具/已开具/已红冲） |
| 小程序支付 | 订单创建后生成待支付订单和支付截止时间；支付成功后支付状态变为已支付 |
| 支付成功后置动作 | 支付成功后自动生成支付记录、学习权益；含实物订单生成待发货任务；订单进入可申请开票状态；生成站内支付成功通知，学员授权订阅消息时同步发送；通过手机号或外部联系人ID匹配线索并回写为已转化 |
| 支付超时 | 超过支付截止时间仍未支付，支付状态自动变为已关闭 |
| 继续支付 | 未超时待支付订单可重新拉起支付 |
| 退款申请 | 学员提交退款申请后生成退款单，退款状态为审核中，订单支付状态保持已支付 |
| 退款状态 | 统一使用审核中、已拒绝、退款处理中、待人工退款、退款失败、已退款，不再使用已通过作为终态或页面状态 |
| 审核通过 | 已接入原路退款时退款单进入退款处理中；未接入或需线下处理时进入待人工退款 |
| 审核拒绝 | 退款单状态变为已拒绝，订单支付状态保持已支付，退款状态变为已拒绝 |
| 原路退款 | 退款结果回写退款单；成功后状态为已退款，失败后状态为退款失败，可重试或转待人工退款 |
| 人工退款 | 待人工退款由财务/代账处理并上传退款凭证，登记退款时间、退款渠道和凭证号后状态变为已退款 |
| 退款成功副作用 | 冻结或撤销学习权益，停止后续课程/发货提醒；已开票订单生成红冲待办；含实物订单根据履约状态判断是否需要先退货或人工确认；对账记录纳入退款金额核对 |

## 4.物流联动

| 场景 | 联调约定 |
|---|---|
| 发货 | 管理员确认发货后获取运单号和面单数据，保存至订单物流信息 |
| 发货失败 | 内部订单履约状态和库存扣减回滚；外部物流、面单或打印已产生结果但内部未完成时，进入异常待处理，由仓管人工补偿 |
| 物流轨迹 | 运单轨迹更新后同步到订单物流详情 |
| 物流费用 | 若物流平台返回费用，进入物流成本；若不返回费用，由月结账单或人工录入补充 |
| 面单打印 | 毕设演示可采用下载面单或保存运单信息；云打印作为扩展能力，需要额外配置打印机设备 |

## 5.开票与红冲

| 场景 | 联调约定 |
|---|---|
| 自动开票 | 接入电子发票后，PC 开票管理点击自动开票发起电子发票开具，成功后变为已开具 |
| 未接入电子发票 | 不展示或禁用自动开票能力，开票申请进入待开具，由代账人员人工开票并上传凭证 |
| 自动开票失败 | 状态变为待开具，记录失败原因，由代账人员人工开具并上传凭证 |
| 手动开票 | 代账人员填写发票号码、开票时间并上传发票文件后，状态变为已开具 |
| 红冲 | 已开具发票发生退款、开票错误等情况时生成红冲待办；接入电子发票后可自动发起红冲，未接入时由代账人员上传红字发票或处理凭证，完成后状态变为已红冲 |
| 税额计算 | 发票与订单关联，开票税率取订单课程/规格的税务规则快照，单一规格按含税金额拆分计算；混合规格先按规格内金额拆分为多条明细，再分别计算税额并汇总 |

## 6.收款对账

| 数据来源 | 用途 |
|---|---|
| 系统订单 | 提供订单编号、商户订单号、订单金额、支付状态 |
| 微信支付结算单/交易账单 | 提供实际支付、退款、手续费、到账等资金记录 |
| 对账结果 | 匹配成功、金额差异、手续费差异、未匹配、重复记录 |
